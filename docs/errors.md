# 错误处理

本文件规定跨层错误的描述、记录与展示。轮次、工具与外部执行各自保留原有状态模型；错误分类不授予重试或外部写入权限。

## 1. 错误描述

应用边界的故障使用结构化 `failure`：

| 字段 | 含义 |
| --- | --- |
| `code` | 稳定错误类别，无法确定时使用未知错误类别。 |
| `message` | 安全、简短的用户说明，不直接拼接异常正文或堆栈。 |
| `source` / `stage` | 出错的边界及阶段，不推测尚未确认的根因。 |
| `impact` | 请求失败、工具失败、轮次失败、辅助降级或外部执行存疑。 |
| `recovery` | 处理建议，不等于安全重试资格。 |
| `diagnostic_id` | 关联页面、持久记录与服务端诊断日志的编号。 |
| `details` | 边界显式选择的安全协议元数据，不包含凭证、请求正文或局部变量。 |

已知业务错误继续提供字段校验、当前版本等信息，供用户或 Agent 修正输入。HTTP、MCP 与轮次错误使用一致的分类；未预期的接口异常返回 JSON 服务端错误。

## 2. 边界职责

- SDK 适配层根据显式错误字段区分认证、计费、限流、服务不可用、请求拒绝与运行时异常。仅有 `refusal` 时报告模型拒绝；内容过滤必须有明确过滤信号或 SDK 合成错误消息中的已知过滤提示，不能根据正文推断。
- 工具失败交回 Agent，并记录工具轨迹；不自动将工具失败提升为整轮失败。调用正常返回与业务执行成功必须分别判断。
- 轮次失败保存简短说明与结构化原因，时间线及 SSE 使用同一份记录。已流出的正文和已发生的工具事实保留，轮次失败不代表此前操作被撤销。
- 外部执行调用异常或结果不符合契约时保守记录 `unknown`，不自动再次执行。核实异常单独记录，保留原执行结论与原因；核实取得成功证据后才升级结论。
- 后台记忆回顾、技能复盘失败独立记录，不改变前台成功轮的结论。标题生成失败保留原标题；完成后的后台登记失败只降级；观测失败不得阻断业务。

## 3. 持久化与诊断

轮次和时间线保留结构化原因；后台回顾与复盘保留对应失败记录；外部执行的异常信息随执行结果保存。历史记录缺少结构化原因时保留原说明，不根据旧文字补造分类。

服务端诊断记录故障编号、类别、来源、阶段、异常类型及调用位置，不输出异常值、局部变量或供应商响应正文。SDK 自身日志属于上游诊断源，应用展示不直接读取或转发其日志正文。

错误记录自身落盘失败时，另记收尾故障并关联原故障编号，释放运行槽位，不发布已保存的假象。数据库不可用期间无法保证故障持久化，遗留运行状态按重启恢复规则处理。

## 4. 展示与恢复

时间线默认只显示一句原因。内容过滤提示为“模型服务因内容过滤停止了回答”；技术字段和处理建议放在默认折叠的错误详情中。

处理建议不自动生成重试按钮。整轮重试仍须通过程序的状态与副作用检查；外部执行存疑先核实；不得自动清空会话、切换模型、重发邮件或再次创建日程。

## 5. 验收

1. 内容过滤发生在部分回答之后时，保留部分回答、展示明确原因，不把 SDK 合成错误文字混入回答。
2. 页面刷新后分类与诊断编号不变，时间线、轮次及观测记录一致。
3. 已知业务错误仍保留模型或用户修正输入所需的字段。
4. 未知异常中的凭证样例不进入 HTTP、MCP、时间线、执行回报或应用诊断日志。
5. SDK 收尾异常不覆盖已确认的上游错误；状态写入失败不谎报完成。
6. 外部执行异常保持存疑，核实异常不降级或覆盖已有执行事实，不产生重复外部写入。
