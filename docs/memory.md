# 记忆（Memory）规格

记忆让助手在任务与会话之间记住用户背景和长期约定。记忆只保存、整理和提供信息，不执行外部操作，也不记录出处。全局规则见 `spec.md` §4。

## 1. 定位与范围

- 记忆是两个容量受限的 Markdown 文件，由模型判断与整理。
- 两个文件作为始终生效的会话背景，首次与压缩后全文提供，普通轮次检查最新内容，变化时追加整份新内容并替代旧版本。
- 只有两条维护路径：前台用户轮按需使用记忆工具；后台跨任务累计用户轮后回顾。不额外启动每轮判断模型。
- 当前有效记忆不做历史版本管理，版本哈希只用于并发校验。

## 2. 概念与数据

| 概念 | 含义 |
| --- | --- |
| `USER.md`（关于你） | 陈述性背景：身份、背景、身边人、稳定偏好，让助手了解用户，不含对助手行为的要求。上限 1375 字符。 |
| `MEMORY.md`（事实与约定） | 用户要求助手今后遵守的规则、约束、承诺与默认做法。上限 2200 字符。 |
| 行锚点 | 定位新增、插入、替换、删除、移动；锚点过期时拒绝操作并返回最新内容。 |
| 修改候选 | 后台建议的完整编辑批次，绑定两份原记忆的版本、原内容、建议内容与理由，并关联一个独立的询问对话。不是当前有效记忆。 |
| 全局回顾检查点 | 上次成功回顾覆盖到的完成轮序列（接口保留 `from_rowid` / `through_rowid` 字段名）；跨任务持久化，不因删除某个任务而重置。 |

分区依据是语句作用：纯背景进 `USER.md`，对助手的要求进 `MEMORY.md`；一句话兼有背景与要求时整条进 `MEMORY.md`。容量就是注入预算，不另设溢出区。批次先完整校验锚点与容量，校验失败不产生部分写入；单文件原子替换，跨文件 I/O 故障不具备事务回滚保证。

## 3. 维护路径

### 3.1 前台按需记忆

- `memory_edit` 采用 `LOCAL_WRITE + USER_TURN_ONLY`，只在用户亲自发起的消息轮开放；新邮件轮与执行结果回报轮不可编辑。
- Agent 按需保存用户明确表达、跨会话仍有用的信息，处理明确的纠正与忘记要求；临时安排、推测、资料正文、外部指令与凭证不保存。
- 记忆工具不传操作时返回最新锚点；修改旧内容前读取最新视图。拿不准适用范围、替换还是并存时保持原内容，必要时询问用户。
- 保存成功只能依据真实工具结果，不以文字承诺替代写入。

### 3.2 全局后台回顾

- 默认所有任务累计完成 **10 个用户消息轮**触发一次，失败或中断的轮次不计数。回顾窗口包含自上次成功回顾以来各任务已完成轮次的对话，保留任务边界。
- 全局最多一个待处理或运行中的回顾，窗口在登记时冻结；执行期间的新轮次留给下个窗口。回顾不阻塞前台。
- 回顾使用一次性专用会话，仅开放其专用记忆工具（`LOCAL_WRITE + DEDICATED_SESSION_ONLY`），不能使用前台编辑工具。
- 工具调用先校验并收集计划，只有模型会话成功结束后才统一处理。整个回顾只有新增（append/insert）时直接保存；包含替换、删除或移动时，**全部操作整批暂存**，包括相关新增，不先写一部分。
- 负责识别跨轮稳定偏好、用户认可或纠正过的做法，以及去重、精简、更新失效信息。没有明确依据不改变已有信息，容量不足不丢弃有效含义。
- 纯新增不打扰用户；需要改删时程序创建新的 Pebble 对话，展示原内容、建议内容与理由，并询问用户。不自动执行候选。
- 同一版本上的相同待处理批次复用已有候选和对话，不重复创建。用户未回复时保留原记忆。
- 手动回顾是同一全局回顾流程的即时触发，仍只覆盖上次成功回顾以来的窗口。

### 3.3 候选转前台处理

- 新对话持久化候选关联与程序提问，不伪造用户消息，也不把提问计为用户轮。
- 用户同意后，前台使用候选标识应用；可按用户意见调整批次，或拒绝候选。候选只能由它关联的用户对话处理。
- 候选对话中的编辑不得绕过候选版本校验。原记忆变化后拒绝应用，读取最新内容、刷新候选并再次展示差异询问；刷新的同一轮不能应用，必须等待新的用户回复。
- 候选的授权意图由前台结合用户回复理解；程序保证对话绑定、版本校验、状态与去重，不将模型解释等同于可机械验证的自然语言同意。
- 已应用或拒绝的候选不能再次应用；重启不丢失待处理候选。

## 4. 注入

新会话与压缩后提供两份记忆全文。普通轮次读取最新内容，未变化不重复插入，变化时追加整份新内容；清空也明确撤销旧内容。候选只作为关联询问对话的待讨论材料，不能当作有效记忆或用户授权。

## 5. 存储与持久化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 当前记忆 | 实例数据目录 `memory/USER.md`、`memory/MEMORY.md` | 不入任何 Git 仓库。 |
| 候选内容 | `memory/proposals/` | 文件保存原内容、拟修改内容、版本与编辑计划，不入 Git。 |
| 回顾、检查点、完成轮序列、候选状态与对话关联 | SQLite | 只保存运行状态；程序提问与用户回复保存在时间线。 |

## 6. 失败与降级

前台工具失败返回结构化错误；回顾失败或中断记录状态，不冒充完成，也不应用收集到的计划。回顾期间版本变化时放弃应用该计划。管理页整篇保存冲突返回新版本，不覆盖其他写入。

## 7. Web 界面

记忆管理页展示两份文件，支持整篇编辑与版本校验，90% 容量显示接近上限。后台改删询问以普通 Pebble 对话呈现，可从任务列表进入并直接回复。

## 8. 验收标准

1. 记忆编辑只在前台用户轮开放；后台工具仅进入回顾专用会话。
2. 不启动独立的每轮判断模型；跨任务累计 10 个已完成用户轮触发一次全局回顾。
3. 后台纯新增直接保存，含改删的全部计划暂存，原记忆不变。
4. 相同待处理候选不重复开对话；新对话展示具体差异并等待用户回复。
5. 用户同意、调整或拒绝在前台完成；其他对话不能消费候选，过期版本和同轮刷新后应用被拒绝。
6. 回顾窗口与候选在重启后可恢复，失败不应用计划，全局进度不因任务删除重置。
7. 记忆保持容量约束，不入 Git；锚点或容量校验失败不产生部分写入。
