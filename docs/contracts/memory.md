# Memory 与历史检索契约

产品行为以 `docs/memory-spec.md` 为准；本文定义长期记忆的文件格式、每轮装配、写入工具、管理接口与历史对话检索的字段和语义。实现与本文冲突时先改本文。

Memory 保存关于用户的精简背景、偏好、长期目标与约定，每轮常驻上下文；个人资料库保存具体资料，按需检索，见 `personal-kb.md`。记忆不记录出处。

## 1. 存储与文件格式

```text
<data_dir>/memory/USER.md   # 用户本人：背景、目标与偏好
<data_dir>/memory/MEMORY.md # 用户以外、跨任务都成立的事实与约定
```

`memory/` 不做版本管理，不进入数据目录的 Git 仓库。

`USER.md`：

```markdown
- 用户默认使用简体中文。
- 用户偏好先给结论，再解释原因。
```

`MEMORY.md`：

```markdown
## 会议

- 内部会议默认 30 分钟；对外邀请按对方给出的时长。
```

每个文件是一份完整的 Markdown 文档，写法不限，不按条分隔。内容按规范化后计数：统一换行、去掉首尾空白、连续空行合并为一个。旧格式中独立一行的 `§` 分隔符在启动时换成空行，原条目变为段落。`USER.md` 最多 1375 个 Unicode 字符，`MEMORY.md` 最多 2200 个；使写入后内容超限且变大的写入整体拒绝，不截断旧内容。文件被直接编辑到超限时照常读取，只接受让它变小的写入。写入是原子替换，不做版本管理；每块记忆的版本号 `version` 是规范化内容的哈希，只用于管理页的冲突检查。

每轮上下文重新读取文件：`USER.md` 作为 `## 关于你`，`MEMORY.md` 作为 `## 事实与约定`，资料目录（`personal-kb.md` 第 7 节）作为 `## 资料目录`，放在本轮触发材料之前。空文件不生成材料块。这三块构成常驻上下文，总量受各自容量上限约束；历史对话、资料正文、邮件与日程不自动注入，由 Agent 按需检索。规则不得覆盖外部写确认约束：该约束由程序（每轮工具可见范围与 Confirmation）保证，不依赖规则文本或模型自律。

## 2. 写入会话与工具

Memory 不向前台对话暴露工具，写入集中在两个独立的一次性会话，都不接续对话、不进入任何任务历史：

| 会话 | 时机 | 工具 |
| --- | --- | --- |
| 每轮记忆判断 | 每个用户消息轮与主回答并行 | `memory_edit` |
| 后台记忆回顾 | 每攒够若干个已完成消息轮，找跨轮模式并整理 | `memory_edit` |

分区：`user` 写用户本人（身份、长期目标、学习方向、兴趣、沟通与表达偏好、工作习惯、对助理的总体期望），`memory` 写用户以外、跨任务都成立的事实与约定（账号、日历、联系人的事实，固定安排规则，使用服务时确认过的经验）。内容写成陈述句，不写成对助理的命令。分区标准与示例写在 `memory_edit` 的工具说明里，判断与回顾共用。

两个会话收到的当前记忆是带锚点的视图：每个非空行写成 `锚点| 原文`，空行原样保留、没有锚点，空分区显示“（空）”；材料标题附带已用与上限字数。锚点是 4 位小写字母或数字（`[a-z2-7]`），由“分区名 + 这一行去掉行尾空白后的文字”哈希得到，两个分区合起来唯一，碰撞或重复行由程序按出现顺序确定性顺延；锚点每次从当前内容现算，不写入文件。某一行被改动后它的锚点随之失效，不需要会话版本号。

`memory_edit` 只输入 `operations`：一组修改，每项必须写 `action`。

| `action` | 必填 | 可选 | 语义 |
| --- | --- | --- | --- |
| `append` | `target`、`text` | — | 加在该分区末尾 |
| `insert` | `after`、`text` | — | 作为新的行插在锚点行下面，同一段；多处插在同一行下时按列表顺序 |
| `replace` | `anchor`、`text` | `end_anchor` | 用 `text` 替换 `anchor` 到 `end_anchor` 的整行 |
| `delete` | `anchor` | `end_anchor` | 删除这些行 |
| `move` | `anchor`、`to` | `end_anchor` | 把这些行移到另一分区末尾 |

规则：
- 一次调用里的锚点都指调用前的内容，可以同时改两个分区；整体生效或整体失败，任何一处出错两个分区都不变。
- `text` 去掉两端空白后不能为空，可以多行（每行去掉行尾空白与首尾空行，保留缩进）；任何一行以锚点前缀（`xxxx| `）开头即报错，程序不替模型删除。`end_anchor` 必须与 `anchor` 同一分区且不在它之前；`to` 必须是另一个分区。
- 两处 `replace`、`delete`、`move` 的范围重叠时报错；`insert` 的锚点行在同一次调用里被删除或移走时报错，被替换时插在替换后的内容下面。
- 单行 `replace` 时原行带列表符号而 `text` 不带，保留原符号；其余原样写入。
- 追加（`append` 与 `move` 的写入端）：分区最后一行是列表项、新文字每一行也都是列表项时紧接其后，否则空一行成为新段。
- 查重只对 `append`、`insert` 与 `move` 的写入端做、只比较写入的分区：新文字逐行去掉列表符号与两端空白，与分区中（含本次调用已写入的）完整行比较；每一行都已存在时不写入，`move` 此时只删除源内容。只有部分行已存在时照常写入。`replace` 新旧相同时不改动。
- 容量按每个改动过的分区的最终结果检查：超过上限且比原来变长时整次拒绝；原本超限的分区变短即允许。写入时先写变长的分区，再写变短的分区。

成功输出 `changed`（整次调用是否改动了记忆）、`applied[]`（按顺序：`action`、`target`，移动另有 `from`、`to`，`removed`/`added` 为程序实际删除与写入的整行，`changed`，未改动时 `reason` 为 `exists` 或 `same`），以及 `memory`：改动过的分区各自带锚点的最新 `content` 与 `usage`。几处修改互相抵消、分区没有变化时每处都记为未改动。判断存在歧义时不调用工具、不写入。

每轮判断完全静默，不写任务时间线。后台回顾实际生效的替换、删除与移动由程序按 `applied[]` 渲染成用户可见提示（见 `memory-spec.md` §5.3），模型自述不作为事实来源；回顾的新增与失败不提示。回顾提示以 `notice` 写入任务时间线，挂在回顾窗口内最后一个调用上，并经 SSE 推送。

管理页面的 HTTP 接口：

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `GET /api/memory` | — | `user`、`memory` 各含 `content`（全文）、`usage`（`chars`、`limit`）、`version` |
| `PUT /api/memory/{target}` | `content`（整份文档，可为空）、`expected_version` | `target`、`changed`、`content`、`usage`、`version` |

页面整份保存；`expected_version` 与当前内容不一致时返回 409 `version_conflict`，附 `current_version`，不写入。内容规范化后与当前一致时 `changed` 为假，不写文件。

## 3. 历史对话检索

Agent 有两个只读工具，所有轮次可用：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `history_search` | `query`（含空格时按多个词处理，全部命中才算命中）、可选 `after`、`before`（`YYYY-MM-DD`，含当天，按本机时区的自然日）、可选 `max_results`（默认 10，上限 20） | 从新到旧的命中：任务 ID 与标题、条目 ID、说话方（`user`、`assistant`、`notice`、`mail_draft`）、时间与片段；默认排除当前任务 |
| `history_read` | `task_id`、`item_id`（取自 `history_search`）、可选 `before`、`after`（前后各取几条，默认 5，上限 20） | 前后原文、`has_earlier`、`has_later`，命中条目标 `matched`；邮件草稿条目附最新收件人、主题、正文、状态与执行结果 |

- 可检索的是已结束轮次里的用户消息、Agent 回答、程序提示与邮件草稿（收件人、主题、正文与状态）；进行中的轮次不可检索，错误条目不检索。
- 检索用与资料库相同的 FTS5 trigram 全文检索。
- 索引（`history_items`、`history_fts`）是可从时间线重建的派生数据，检索前增量同步：新条目补入，草稿改版或执行状态变化后重写；删除任务时一并清除。
- 页面搜索接口 `GET /api/history/search`：`q`、可选 `after`、`before`、`limit`（默认 20），与 `history_search` 同一套检索，不排除任何任务。

## 4. 错误

通用错误见 `v1-design.md` §3。Memory 字段校验（含页面接口的未知分区）、锚点不存在或修改范围冲突返回 `invalid_memory` 并附 `errors[]`（HTTP 422），模型工具调用出错时另附 `memory`（两个分区带锚点的最新内容与用量）；容量超限返回 `memory_full`，附 `target`、`used`、`limit` 与 `memory`（HTTP 422）；文件不可读写返回 `memory_store_unavailable`（HTTP 503）。失败不保留文件的半完成修改。历史检索参数不合法返回 `invalid_history`（HTTP 422），附 `errors[]`。
