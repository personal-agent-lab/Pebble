# Pebble 轨迹追踪与可观测性规格

本文只规定任务页中可核对的执行过程。接口和存储语义见 contracts/observability.md；实现状态只写在 status.md。

## 1. 分工

**执行轨迹**回答“实际发生了什么”：用户消息、Agent 回答、每次工具尝试及其结果、用户纠正，仍保存在任务时间线中，供 Skill 复盘引用。Pebble MCP 工具和本轮开放的 Qoder 内置工具（当前为 WebSearch、WebFetch、附件 Read）都属于工具尝试。工具成功只表示调用成功，轮次结束也不表示用户目标达成。

**运行观测**回答“这一轮为什么变成这样”：输入材料是否装入、模型和工具耗时、调用次数与用量、上下文占用、压缩、权限拒绝和影响本轮结果的静默降级。观测供人排查，不作为 Skill 复盘证据，不评价 Agent 的做法。两者通过轮次和工具条目标识互相定位，不复制工具正文。

## 2. 任务页

对话时间线保持原有阅读顺序。每轮附一个默认折叠的「执行详情」；运行中可看到当前已开始的工具，结束后可看到：

- 本轮组装了哪些类别的材料、各有多少字符；明确跳过的材料及原因。这里表示 Pebble **提交给 SDK** 的材料，不声称能还原模型内部最终看到的全文。
- 本轮总时长、SDK 报告的 API 时长和模型调用次数；每次工具调用的起止、耗时与状态。两类时长分别标注，不通过相减臆造“纯思考时间”。
- 本轮各次模型请求由 SDK 报告的 token／Credits 用量与上下文占用。缺少请求级用量时显示“未记录”，不拿会话累计值冒充本轮消耗。
- 发生的压缩、实际被拒的工具尝试，以及本轮材料或辅助判断未完成但主回答继续的情况。

工具行与对应执行详情可以互相跳转。工具参数和返回内容只在现有轨迹条目中展开；运行观测只显示名称、状态、耗时、返回规模与引用。邮件发送和日程创建的最终状态继续从 Confirmation 的既有记录读取，不复制一份结论。

## 3. 记录边界

- 随任务自动记录，只保存在单实例本地 SQLite；删除任务时一起删除。观测写入失败只记进程日志，不中断对话、工具或外部写入；界面把缺失显示为“未记录”，不推断“没有发生”。
- 观测不存提示词、材料全文、工具参数或返回正文、附件内容、凭证、SDK 原始选项、MCP 端点路径及其一次性令牌。材料只存类别、字符数和装配／跳过状态；降级只存类别与必要的计数或标识。
- 不新增独立的 Agent 循环，不改变工具可见范围、授权、Confirmation 或 Skill 复盘规则。

## 4. 验收

1. 用真实 Qoder CN SDK 分别调用 Pebble MCP 工具与成功的内置工具，确认轨迹有且只有一条对应调用，参数、结果、状态和顺序正确；执行详情显示起止与耗时，能跳到轨迹条目。内置工具失败与实际到达权限回调的拒绝也能区分。
2. 一轮带材料的任务能核对实际装配与跳过情况；构造技能未装配和记忆判断失败，主回答继续，执行详情能解释原因。
3. 真实运行一轮并触发一次压缩，核对 SDK 回报的时长、调用次数、每次模型请求的用量与上下文占用；会话累计值不冒充本轮消耗。
4. 运行中、刷新后和服务重启后，已记录的步骤与轮次状态一致；缺失数据标“未记录”。观测数据里搜不到正文、凭证与工具端点令牌；删除任务后观测记录消失。

官方 Python SDK 文档列出 PreToolUse、PostToolUse、PostToolUseFailure 回调及成功调用的工具返回字段；本地 qodercn-agent-sdk 1.0.14 也声明了这些类型。它们说明存在接入路径，**不代替第 1 项的真实 CN 运行时验收**：[Python SDK 参考](https://docs.qoder.com/cli/sdk/references-python)、[CLI 工具回调](https://docs.qoder.com/cli/hooks)。用量字段的不同口径见 [Cost and usage](https://docs.qoder.com/cli/sdk/cost-usage)。
