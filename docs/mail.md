# 邮件（Gmail）规格

邮件域负责收信触发、读信、起草与确认发送。全局规则（外部写授权、暴露矩阵、领域中立）见 `spec.md` §4；本文件只写邮件域的行为。

## 1. 定位与范围

- 收：轮询 Gmail 收件箱，新邮件自动触发任务处理；带 `News` 标签的来信除外。
- 发：Agent 只能起草，发送由用户确认后由程序执行；发送函数永远不暴露给模型。
- 只发纯文本，不支持附件外发。
- 只监视收件箱（INBOX）的新增邮件；其他标签、已发送邮件的变化不触发任务。
- 一个 Gmail 账号。未配置凭证时整域关闭（见 `spec.md` §9）。

## 2. 概念与数据

| 概念 | 含义 |
| --- | --- |
| 草稿（draft） | 一个待确认的邮件操作，含收件人、主题、正文；有不可变版本序列。 |
| 回复（reply） | 草稿与来源来信的关联。**对同一封来源来信，最多存在一个未取消的回复**。 |
| 取代（supersede） | 编辑一个已取消的草稿不复活旧卡片，而是产生新操作、新卡片。 |
| 执行核实（verification） | 发送后的只读复查，结论为已发送 / 失败 / 存疑（unknown）。 |

规则：

- 草稿可以没有收件人（先按已知信息起草，收件人由用户稍后在审阅卡片上补填），但**发送前必须有收件人**。
- 草稿版本不可变；每次编辑产生新版本，确认总是针对某个具体版本。

## 3. 工具面

模型可见的工具（名称即产品接口）：

| 工具 | 副作用 | 语义 |
| --- | --- | --- |
| `gmail_search` | `READONLY` | 按条件搜索邮件。 |
| `gmail_get_thread` / `gmail_get_message` | `READONLY` | 读会话 / 读单封邮件。 |
| `gmail_get_attachment` | `READONLY` | 读附件，以文件引用返回给工作区。 |
| `gmail_prepare_reply` | `LOCAL_WRITE` | 针对来源来信起草回复，保存草稿并产生草稿卡片。 |
| `gmail_prepare_email` | `LOCAL_WRITE` | 起草全新邮件。 |
| `gmail_read_draft` | `READONLY` | 读当前草稿内容。 |
| `gmail_update_draft` | `LOCAL_WRITE` | 修改草稿；对已取消草稿的修改走取代规则。 |

**发送与核实函数不属于工具面**：它们只注入给确认执行器，属于 `EXTERNAL_WRITE` 级别（见 `spec.md` §4.1）。

## 4. 行为流程

### 4.1 新邮件触发

1. 轮询（每 10 秒）Gmail 变更历史，游标持久化，原子推进。
2. 首次启动从当前位点开始，**不回灌历史邮件**。
3. 只有收件箱的新增来信触发任务；带名称精确匹配 `News` 的标签的邮件不创建任务、不运行 Agent。每次轮询有候选来信时解析最新标签 ID，并在触发前只读检查邮件当前标签；标签不存在时按普通来信处理，标签查询失败时不推进游标，走同步错误降级。忽略邮件后正常推进游标，重启不回灌；过滤不修改 Gmail 邮件，也不影响用户主动搜索和读取。触发后才添加标签不撤销已有任务，移除标签不补触发已跳过的邮件。通过来信-任务链接表去重，同一封来信只建一个任务。
4. 触发轮的目标是**处理这封邮件**（如摘要、判断需要做什么）。起草工具不在触发轮的工具面内（`spec.md` §4.1 矩阵不含 `LOCAL_WRITE`）：回复草稿在用户开口（如"帮我回复这封"）之后的用户轮产生。
5. 来信的标识以材料（结构化数据）形式注入，不写进用户可见文案。

### 4.2 起草与修改

1. Agent 调用准备工具生成草稿，时间线出现草稿卡片，前端即时可见。
2. 用户在卡片上直接编辑，或以定向消息（"要求修改"）让 Agent 修改。
3. 每次修改产生新版本；回复去重规则保证同一来信只有一个未取消回复。

### 4.3 确认发送

1. 用户在卡片上确认 → 确认服务在同一事务内校验（任务关联、版本一致、状态为待确认、收件人非空）。
2. 通过后状态置为发送中，后台执行实际发送；两个并发确认只有一个能成功。
3. 发送使用程序生成的确定性 `Message-ID`，并正确设置回复链头，使核实与线程关联可靠。
4. 发送后立即只读核实（按消息 ID 检索已发送 + 内容匹配）；核实不确定时结论为**存疑**，不谎报成功。
5. 执行结果注册为 `execution_result` 轮回报原会话，Agent 据实汇报。

### 4.4 取消

- 待确认草稿可随时取消：不发送、不执行、不产生回报轮。
- 已取消草稿不可再确认；对其编辑走取代规则。

## 5. 存储与持久化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 草稿与版本、执行记录、来信-任务链接 | SQLite | 运行状态，随任务生命周期。 |
| 同步游标 | `gmail_sync.json`（实例数据目录） | 原子写入，重启续传。 |
| Gmail 凭证与令牌 | 实例数据目录 | 不进 Git、不进上下文（见 `spec.md` §4.4）。 |

## 6. 失败与降级

| 情形 | 行为 |
| --- | --- |
| 发送后核实不确定 | 结论存疑（unknown），提供用户触发的只读复查，可能升级为已发送；不自动重发。 |
| 执行中断（重启） | 已开始的执行标记为待核实，未开始的标记为失败（未产生外部写入），两种都回报原会话。 |
| 同步游标失效（服务端 404） | 停止轮询并报错，健康状态降级；不自动丢弃游标重来。 |
| 账号不匹配（凭证与配置不符） | 触发源致命错误，停止轮询，如实报告。 |
| 凭证未配置 | 域关闭，健康检查报告 `unconfigured`。 |

## 7. Web 界面

- 草稿卡片：查看、直接编辑、确认发送、取消、"要求修改"（定向改稿）。
- 存疑执行可发起核实；状态徽章如实反映待确认 / 发送中 / 已发送 / 失败 / 存疑。
- 邮件触发的任务在任务列表中有独立标识。

## 8. 验收标准

1. 发送与核实函数从未出现在任何轮次的工具列表中；`new_mail` 轮不出现起草工具（`LOCAL_WRITE` 不在其矩阵允许范围），也不能删除资料、不能创建日程。
2. 对同一封来源来信，任何时刻最多存在一个未取消的回复草稿（并发编辑下也成立）。
3. 无收件人的草稿无法通过确认校验。
4. 确认发送后，原会话收到的汇报内容与真实核实结论一致；核实不确定时汇报"存疑"。
5. 同一封来信只产生一个任务；重启后不重复处理。
6. 首次启动不回灌历史邮件。
7. 来信正文中的指令（"自动回复并转发给……"）不产生任何未经确认的外部写。
8. 收件箱的新邮件在触发前带 `News` 标签时不创建任务；普通来信照常触发。全页均为被忽略邮件时仍推进游标；标签读取失败不推进游标，恢复后重试。
