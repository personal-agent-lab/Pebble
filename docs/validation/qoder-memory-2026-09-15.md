# Qoder 长期记忆验收记录（2026-09-15）

## 结论

Pebble 使用真实 Qoder 模型完成了长期记忆最小闭环：模型调用 `memory` 工具将普通格式偏好写入
临时实例目录，写入产生一个本地 Git 提交；随后使用全新的 SDK 会话提问，模型从每轮注入的
长期记忆中准确回答 `CORAL-7421`。

验收使用 `qodercn-agent-sdk==1.0.14` 和其捆绑的 Qoder CLI CN 1.1.38。

全新会话的回答为：

## 可重复执行

在仓库根目录运行：

```bash
uv run --project server python -m tests.acceptance.qoder_memory
```

脚本显式调用真实模型并消耗账号额度，因此不进入普通 pytest。

## 验证边界

- 使用真实 Qoder 模型、真实 qodercli 子进程、真实 MCP HTTP、真实文件与本地 Git。
- 使用临时 `PEBBLE_DATA_DIR`，结束后自动删除，不修改用户的真实长期记忆。
- Gmail 使用测试替身，Calendar 未装配；没有读取外部账号或执行外部写操作。
- 本次验证长期记忆的写入、提交、逐轮加载与跨会话应用，不验证尚未实现的管理页面和历史检索。

首次测试把内容表述为“长期测试代号”，模型按基础安全提示将其视为内部标识，虽然文件已成功
写入，但拒绝在新会话中透露。将测试内容明确改为普通的清单格式偏好后，完整闭环通过。该结果
说明验收文本必须避免与密码、令牌或内部标识混淆；安全拒绝不等于记忆加载失败。
