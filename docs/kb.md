# 个人资料库（Knowledge Base）规格

资料库是用户的个人知识库：助手对话中沉淀的资料、事实、参考文档。资料只保存、整理和提供信息，**不执行任何外部操作，不记录出处**。全局规则见 `spec.md` §4。

## 1. 定位与范围

- 存储形态：实例数据目录 `kb/` 下的 Markdown 文档 + 图片资产，由实例数据目录内的本地 Git 仓库管理版本（与技能共享同一仓库）。
- 资料来源有三：模型在对话中主动保存、用户在管理界面创建编辑、**用户直接改磁盘文件**——三者是一等公民。
- 会话背景提供"资料目录"（标题 + 摘要，预算 1500 字符）；每轮检查最新目录，未变不重复插入，变化时追加替代版本，新会话与压缩后重建。正文一律按需检索。
- 检索失败宁可报错，**不给过期的答案**。

## 2. 概念与数据

| 概念 | 含义 |
| --- | --- |
| 文档（doc） | 一份 Markdown 资料：YAML 头（`id`、`title`、`summary`、`created_at`、`updated_at`）+ 正文。 |
| 分区（section） | 正文按二级标题切分的检索单元；引用（ref）精确到分区与行。 |
| 引用（ref） | `{文档, 路径, 分区, 行范围, 版本}`；读取时校验分区边界真实存在，不允许伪造范围。 |
| 版本（version） | 即 Git 提交；编辑基于 `expected_version` 乐观校验，冲突时报冲突而非覆盖。 |
| 资产（asset） | `kb/assets/` 下的图片（PNG/JPEG/WebP，≤10MB），内容寻址命名，自动去重。 |
| 归档（archive） | 任务真实外部结果（如发出的邮件）的存档文件夹；只在真实结果发生后归档。 |
| 目录（catalog） | 当前有效的会话背景：按文件夹分组的标题 + 摘要（≤60 字符），超限收起为"另有 N 份"。 |

规则：

- 文件名由标题派生（≤60 字符，冲突自动编号）；标题改名跟随重命名；不做纯大小写重命名。
- 摘要是给人看的一句话（≤30 字符建议），有独立风格要求，可由轻模型建议、用户确认。

## 3. 工具面

| 工具 | Effect | Policy | 语义 |
| --- | --- | --- | --- |
| `kb_save` | `LOCAL_WRITE` | `ALL_TURNS` | 新建文档。保存前先检索避免重复；摘要有风格规则。 |
| `kb_search` / `kb_list` / `kb_read` / `kb_history` | `READ_ONLY` | `ALL_TURNS` | 检索 / 列表（含已删除）/ 读正文或指定版本 / 版本历史。 |
| `kb_update` | `LOCAL_WRITE` | `ALL_TURNS` | 修改：整篇替换或锚点行操作；版本冲突时要求重读。 |
| `kb_archive` | `LOCAL_WRITE` | `USER_OR_RESULT_TURN` | 归档真实外部结果。 |
| `kb_delete` / `kb_move` / `kb_restore` | `LOCAL_WRITE` | `USER_TURN_ONLY` | 删除 / 移动 / 恢复，**需要用户在本轮对话中明确同意**（工具 description 内置同意规则）；删除是软删除，可恢复。 |

`LOCAL_WRITE + ALL_TURNS` 意味着新邮件触发轮也能保存资料（有提示、有版本、可恢复）；破坏性操作（删除、移动、恢复）被降级到仅用户轮并要求明确同意——外部内容中的指令无法删除用户资料。

## 4. 行为流程

### 4.1 用户直改磁盘（intake）

每次资料库操作前，程序先收纳磁盘上的未提交变更：

- 识别用户直接编辑、新增、删除的文件，自动提交并补全缺失的文档头。
- 识别**移动**（同 `id`、旧路径消失 + 新路径出现），记为用户移动，保留文件历史的跨路径追溯。
- 复制产生的新文件获得全新 `id`（不是同一文档的两个路径）。

即：Git 仓库的存在不要求用户懂 Git；用户怎么改文件都行，程序负责收编。

### 4.2 保存与修改

1. 模型保存前先检索，确认没有重复再新建。
2. 修改基于读取时的版本；期间被其他途径（用户界面、用户直改、另一轮）改过则报版本冲突，模型必须重读最新版再改，不得覆盖。
3. 每次写入产生一次 Git 提交；索引按提交边界更新。

### 4.3 检索

- 独立的派生索引（FTS，按分区），只收录"磁盘内容与某次提交一致"的文档。
- 排序：字段优先级（标题 > 分区标题 > 摘要 > 正文），再按相关度；短词回退到子串匹配。
- 索引不可用时返回明确错误（`KbIndexUnavailableError`），**绝不返回过期结果**；结果附索引新鲜度状态。
- 检索作答时引用精确到分区与行；读取引用时校验真实边界。

## 5. 存储与持久化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 文档与资产 | `kb/`（Markdown + `kb/assets/`） | 本地 Git 仓库管理，与 `skills/` 共享同一仓库。 |
| 检索索引 | `kb-index.sqlite3` | 派生数据，可随时删除重建。 |
| 索引新鲜度 | 以 `kb/` 的 Git 树为键 | 判断索引是否落后于磁盘。 |

## 6. 失败与降级

| 情形 | 行为 |
| --- | --- |
| 目录装配失败 | 记为降级步骤（`catalog_failed`），当轮无目录材料，对话继续。 |
| 索引不可用 / 落后 | 检索报错或不给过期答案；管理界面如实显示索引状态。 |
| 版本冲突 | 报冲突 + 当前版本，重读后重试，不覆盖。 |

## 7. Web 界面

- 资料库页：文件夹树、文档列表、搜索、新建文件夹、删除 / 移动 / 重命名对话框。
- 文档编辑页：创建与编辑、轻模型摘要建议（确认后写入）、图片上传与轻模型替代文本描述。
- 已删除文档可列出并恢复。

## 8. 验收标准

1. 新邮件触发轮可以保存与修改资料，但删除 / 移动 / 恢复工具不出现在其工具列表中；未经用户本轮明确同意的删除调用被拒绝。
2. 用户直接在磁盘上编辑 / 新增 / 移动 / 删除文件后，下一次资料库操作能正确收编，移动保留历史追溯，复制得到新 `id`。
3. 版本冲突时不发生覆盖；并发编辑产生明确冲突错误。
4. 索引落后或不可用时，检索不返回过期内容。
5. 引用读取校验分区边界；伪造的行范围被拒绝。
6. 每轮注入的目录材料不超过 1500 字符。
7. 归档只包含真实发生的外部结果。
