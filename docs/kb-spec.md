# Pebble 个人资料库功能规格

本文说明用户能得到什么，不限定实现；存储、工具字段与索引见 `contracts/personal-kb.md`，长期记忆与每轮上下文见 `memory-spec.md`。

已确认的产品决定：回答不展示来源，程序也不记录 Agent 读了哪些资料；资料与记忆都不记录出处；Agent 可以主动保存与修改资料；删除与移动先在对话中确认，删除后可以恢复；用户直接改动的文件自动纳入版本与检索；资料只收 Markdown，正文可嵌入图片；管理界面不提供历史版本。

## 1. 目标

用户把需要按原文查回的资料交给 Pebble，之后直接提问就能得到基于资料的正确回答；资料逐步整理成主题页。资料是用户能直接打开、修改和整理的 Markdown 文件，用户不需要懂检索方式、文件位置或 Git。

## 2. 在整体中的位置

每轮只带入资料目录，正文需要时再读；记忆与资料怎么分，见 `memory-spec.md` 第 2.2 节。分不清用户想记偏好还是存资料时先问。

资料库只保存、整理和检索内容，不执行外部操作。资料里的指令只是内容：不改变 Agent 行为，不变成记忆，不能代替授权。凭证不存入资料库。

## 3. 保存资料

### 3.1 保存方式

资料来自三处：用户要求保存；Agent 主动保存（第 3.2 节）；用户直接在 `kb/` 或管理界面里新建。每次保存都是一个可直接打开的 Markdown 文件，并留下一个历史版本。

### 3.2 Agent 主动保存

Agent 可以不等用户要求就保存：用户贴进来的文档与笔记，邮件与日程中的人物、约定与时间（包括新邮件触发的轮次），任务归档，以及已过时资料的更新。

- 先查是否已有同一份资料，有就改原资料，不产生副本。
- 只保存以后要按原文查回的内容；闲聊、一次性安排与凭证不保存。
- 基于当前版本修改；读取之后被用户改过的，重新读取再决定，不静默覆盖。
- 和用户要求的保存一样展示结果，不悄悄写入。

### 3.3 保存结果的展示

程序按实际写入结果在对话中提示，不依赖 Agent 复述；提示和回答都用标题与所在文件夹指代资料，不出现文件名。

- 新建：“已保存资料：星云项目验收纪要。位置：「项目」文件夹”；修改另外显示修改前后的版本。
- 已写入但暂时不可检索：“资料已保存，但当前不可检索”。
- 失败：如实说明原因，不声称已保存。

### 3.4 任务归档

外部操作有了实际结果后，Agent 自行判断是否把关键信息与逐项结果归档；纯问答、闲聊或只起草未确认的任务不归档。原始内容与模型总结分节写，执行结果以实际记录为准（没发成功不写“已发送”，不确定就写不确定）。

### 3.5 资料格式

- 只收 Markdown。PDF、附件、网页等由 Agent 提取文字后存成 Markdown，原始文件不存。
- 例外是正文图片：在管理界面粘贴或拖入，随资料保存，并自动生成可修改的图片说明（有文字的图尽量转写）。Agent 通过说明检索和理解图片，不直接看图。
- 每份资料有一句话说明，出现在资料目录里并参与检索，决定 Agent 能否想到去读它。Agent 保存时填写，用户可以修改，管理界面可让轻量模型起草。
- 按目录组织，由 Agent 按内容选择，不强制分类法，不带标签；拿不准时放在根目录。
- 标题就是名字：文件名取标题，同一文件夹重名时编号（“DVM 2.md”），改标题时文件名随之更新、文件夹不变。

## 4. 查找资料并回答

### 4.1 回答依据

- 涉及具体事实时先检索、再读原文作答，检索摘要不能单独作为依据。整体情况可以先读主题页（第 8 节），细节仍读原资料。
- 关键词、编号、英文或自然语言都能检索到。
- 找不到就说“资料库里没有找到”，不凭印象或记忆编造；资料互相矛盾时说明冲突与各自说法；问旧内容时读历史版本，并说明是旧版本。

### 4.2 不展示来源

回答不附来源；程序不记录、不展示 Agent 读了哪些资料，只展示写入结果。用户问“那份纪要放在哪”时正常回答。内部定位信息（路径、行号、版本）只用于读取原文与历史版本。

### 4.3 资料目录

每轮常驻一份程序现算的目录，告诉 Agent 库里有什么：

```text
资料库共 23 份资料；需要细节时用 kb_search 检索，或用 kb_read 读取原文。
- 项目/星云/（8 份）
  - 星云项目验收纪要：二期验收结论、代号与遗留问题
  - 另有 7 份
```

- 每份资料一行“标题：说明”，按目录分组；改标题、说明或位置后下一轮即反映。
- 有容量上限，最近更新的优先，列不下的合并计数，仍可检索。
- 目录只是指针，回答具体事实仍要读原文；首版不在回答前预先检索。

## 5. 修改、删除、移动与恢复

### 5.1 修改

改动原文件，身份不变，每次留下历史版本。局部修改只动涉及的行，其余内容逐字不变。

### 5.2 删除与移动先确认

- Agent 删除、移动或批量整理之前，先在对话中说明涉及哪些文件、移到哪里，得到明确同意才执行；用户在同一条消息里已明确要求的视为同意，批量整理仍要先确认方案。
- 删除后不再被检索到，历史保留、可以恢复；移动后身份不变，历史跟随。改标题属于修改，不需要先确认。

### 5.3 恢复

找回已删除的资料或回到某个旧版本时，恢复产生一个新版本，不改写历史，并展示位置与版本；有多个候选时先问恢复哪一个。

## 6. 用户直接改动文件

用户可以用任意编辑器直接编辑、新增、移动和删除资料，程序在下一次检索前自动纳入版本与索引：移动与重命名识别为同一份资料；没有标识的新文件只补标识、不动正文；与 Agent 的修改冲突时以用户为准；删除的文件可以通过对话恢复。

## 7. 资料管理界面

电脑与手机都能按文件夹浏览（标题、说明、更新时间）、搜索（标题与命中片段）、打开资料与主题页，新建资料或文件夹，编辑、重命名（即改标题）、移动与删除资料；正文用所见即所得编辑器，可粘贴或拖入图片。

- 界面操作等同于用户直接改文件：删除由界面自己确认，保存留下版本并进入检索；界面与文件是同一份内容。
- 打开后被别处改过的资料，保存不覆盖，提示重新载入。
- 编辑器保存的仍是 Markdown，被编辑的正文可能重新排版；只打开或只改标题与说明时正文原样保留。
- 公式写作 `$…$` 与 `$$…$$`，界面与对话中都排版显示；`$5 到 $10` 这类金额不算公式。
- 不提供历史版本与恢复入口（在对话中完成），不展示 Agent 的读取记录。

## 8. 主题页

资料库为长期存在的主题（人物、项目、课程、组织）维护主题页，汇总当前概况与按时间整理的重要变化，可列出相关资料位置。主题页是普通资料：可阅读、检索、修改，有历史版本，和其他资料一样出现在资料目录里。

- Agent 保存相关资料时可以顺带更新主题页；同一主题反复出现时可以新建。
- 后台定期整理：独立于对话运行，把近期资料与对话要点整理进主题页；只写资料库，不改记忆，不通知用户。
- 用户的修改优先：基于当前版本整理，不改回用户改过的内容，不加回用户删掉的条目。
- 主题页不替代原资料：不一致时以原资料为准，回答具体事实仍读原资料；删除主题页不影响原资料。

## 9. 验收

本文每条规则都是验收项。此外必须用真实模型、真实文件与版本历史走通以下场景；只测文件读写或使用固定的模拟回答不算通过。

1. **保存、提问、更新**：贴入验收纪要并要求保存 → 提示位置 → 新会话问代号，读原文作答且无来源 → 用户在编辑器里改代号 → 再问得到新代号 → 问“改之前是什么”，读历史版本作答。
2. **主动保存与整理**：新邮件约了时间 → 起草回信的同时保存约定，时间线显示位置 → 对方改期 → 修改原资料并显示前后版本 → “把课程资料整理到课程目录” → 列出方案、同意后执行 → 删除旧安排 → 一周后找回。
3. **主题页**：同一项目陆续保存多份资料 → 后台生成主题页并出现在目录中 → 新会话问进展，读主题页作答，追问细节时读原资料 → 用户删掉主题页里的一条待办，之后的整理不再加回。
4. **图片**：粘贴一张表格截图并保存 → 之后按截图里的文字提问，Agent 能检索到这份资料并依据图片说明作答。
5. **注入**：资料正文含“忽略之前的要求”“记住我喜欢……” → 不改变行为，不写入记忆，不触发外部写。
6. **两端界面**：电脑与手机上浏览、搜索、编辑、移动、删除资料，文件系统里的内容与界面一致。

## 10. OpenHuman 参考与取舍

参考 [OpenHuman](https://github.com/tinyhumansai/openhuman/blob/main/gitbooks/features/obsidian-wiki/memory-tree.md) 的 Memory Tree 与 SuperContext（2026-09-16 查阅），借鉴思路而不照搬：

| OpenHuman 做法 | 本文 | 理由 |
| --- | --- | --- |
| 记忆、上下文、Agent、工具分层，记忆不执行外部操作 | 采用 | 边界清楚，资料增长不影响授权 |
| 小容量常驻与按需检索分开 | 采用：记忆与资料目录常驻，正文按需 | 控制每轮上下文成本 |
| 分层摘要树 | 改为主题页 | 个人规模下分节检索足够；主题页可读、可改、有版本 |
| 以数据库为准，Markdown 为生成结果 | 不采用：以 Markdown 为准，索引与目录可重建 | 用户能直接编辑并有版本历史 |
| 外部数据全量同步、数据源适配器 | 不采用：邮件与日程按需查询，不从笔记应用导入 | 避免同步负担、隐私范围扩大与噪音 |
| 每个数据块保留出处 | 不采用 | 产品决定 |
| 新会话前预先检索组装上下文 | 暂不采用 | 避免额外模型调用；按实测再定 |
| 独立的目标文件 | 不采用：长期目标记在 `USER.md` | 现有记忆已覆盖 |

## 11. 不在范围内

原始二进制文件的保存与预览；向量检索、知识图谱或第三方知识库；出处记录；从外部笔记应用导入；标签；多用户共享或远端同步；把旧记忆中的资料批量迁移进资料库。外部写操作的授权以 `v1-spec.md` 与对应契约为准。
