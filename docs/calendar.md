# 日历（iCloud Calendar）规格

日历域负责日程查询、冲突检查与事件创建。全局规则见 `spec.md` §4；本文件只写日历域的行为。

## 1. 定位与范围

- 对接 iCloud 日历（CalDAV 协议）。
- 只操作**主日历**：查询、冲突检查、创建事件。不管理多个日历、不修改、不删除事件。
- 创建是会话式直连形态：工具在用户轮内完成"校验 → 冲突检查 → 确认 → 创建 → 内联返回结果"，没有待确认卡片（与邮件的卡片式确认对比见 §4.4）。
- 一个 iCloud 账号。未配置凭证时整域关闭（见 `spec.md` §9）。

## 2. 概念与数据

| 概念 | 含义 |
| --- | --- |
| 事件（event） | 待创建的日程：标题、开始、结束、时区/全天、地点、备注。 |
| 事件版本 | 创建前的本地快照，版本不可变；执行状态与结果关联到具体版本。 |
| 冲突（conflict） | 与既有事件时间重叠。冲突检查在创建前强制执行。 |

校验规则：

- 时间为必填：带时区的完整时间，或明确的全天日期。
- 结束必须晚于开始。

## 3. 工具面

| 工具 | Effect | Policy | 语义 |
| --- | --- | --- | --- |
| `calendar_list_events` | `READ_ONLY` | `ALL_TURNS` | 列出时间范围内主日历的事件。 |
| `calendar_get_event` | `READ_ONLY` | `ALL_TURNS` | 读单个事件详情。 |
| `calendar_check_conflicts` | `READ_ONLY` | `ALL_TURNS` | 检查某时间段与既有事件的冲突。 |
| `calendar_create_event` | `EXTERNAL_WRITE` | `USER_TURN_ONLY` | 创建事件。**仅用户亲自发起的轮可见**（`spec.md` §4.1 矩阵）。 |

`calendar_create_event` 的产品规则写在工具 description 中，模型必须遵守：

1. 只有当**本轮对话中用户已经给出**标题、开始、结束三项时才允许调用；信息不全时先询问，不得猜测或代填。
2. 检测到冲突时返回冲突结果（`status: conflict` + 冲突事件列表），**不创建任何事件、不留任何痕迹**。
3. 只有用户在看到冲突后**明确坚持**，才允许带覆盖标记重新调用。

## 4. 行为流程

### 4.1 查询

用户询问日程时，Agent 用查询工具作答；回答必须基于工具返回的真实数据。

### 4.2 会话式创建

1. 用户在对话中给出事件信息（至少标题、开始、结束）。
2. Agent 调用创建工具 → 程序校验字段 → 强制冲突检查：
   - 无冲突：保存本地事件版本 → 确认通过 → 执行创建 → 工具**内联等待**并返回真实创建结果（含服务端事件标识）。
   - 有冲突：返回冲突列表，流程停在对话中，由用户决定改期或坚持。
3. 创建结果直接进入本轮回复，不需要额外的回报轮（与邮件不同：邮件发送是异步执行 + 回报轮，日历创建是同步内联）。

### 4.3 失败

创建失败时如实报告失败，不重试、不谎报成功；本地版本保留执行状态供追溯。

### 4.4 与邮件确认形态的对比

| | 邮件发送 | 日历创建 |
| --- | --- | --- |
| 形态 | 卡片式：草稿 → 用户点确认 → 异步执行 → 回报轮 | 会话式：对话内给齐信息 → 工具内联执行 → 即时结果 |
| 闸门 | 确认接口 + 事务校验 | 仅用户轮暴露 + 工具内确认服务 |
| 冲突语义 | 收件人校验 | 日程冲突，可被用户明确覆盖 |

两种形态都经由同一个确认服务执行外部写（`spec.md` §4.1）。

## 5. 存储与持久化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 事件版本与执行记录 | SQLite | 创建前的本地快照与执行状态。 |
| iCloud 账号与应用专用密码 | 实例数据目录 | 不进 Git、不进上下文。 |

真实日历数据始终在 iCloud 服务端；本地不缓存日历内容。

## 6. 失败与降级

| 情形 | 行为 |
| --- | --- |
| 创建请求执行中断（重启） | 已开始的标记待核实，未开始的标记失败（未产生外部写入），两种都回报原会话。 |
| 核实不确定 | 结论存疑，允许只读复查升级结论。 |
| CalDAV 服务不可用 | 该次操作失败并如实报告；健康状态相应降级。 |
| 凭证未配置 | 域关闭，健康检查报告 `unconfigured`。 |

## 7. Web 界面

日历域没有独立管理界面；全部交互发生在对话中，创建结果与冲突列表在时间线内呈现。

## 8. 验收标准

1. `calendar_create_event` 在 `new_mail` 轮与 `execution_result` 轮的工具列表中不出现。
2. 信息不全（缺标题、开始或结束）时，Agent 询问而不是调用工具创建。
3. 存在冲突且用户未明确坚持时，服务端不出现任何新事件。
4. 创建成功后，回复中包含真实的服务端事件标识，且在 iCloud 上可查。
5. 创建失败时回复为失败，不出现"已创建"措辞。
6. 全天事件与带时区事件均能正确创建；结束早于等于开始的输入被拒绝。
