# Pebble 记忆功能规格

个人资料库的功能规格见 `docs/kb-spec.md`，两者分工见第 8 节。

本文描述用户能够获得的功能，不限定数据库、检索算法或模型实现；存储格式、工具字段与接口见 `docs/contracts/skills.md`。

## 1. 产品目标

让 Pebble 在长期使用中了解你，并能找回过去的讨论。你不必每次聊天都重复背景，也不必记住信息出现在哪次对话里。

你可以直接说：

- “记住，我希望先看结论，再看解释。”
- “上周我们为什么放弃那个方案？”
- “参考上次讨论的意见，继续完善我的研究计划。”
- “把我刚才说的偏好改掉。”
- “忘记我偏好英文回答这件事。”

Agent 按问题自行选择需要的信息。用户不需要先选择搜索工具或记忆类型。

## 2. 三类信息分别做什么

| 类别 | 保存什么 | 用户获得什么 |
| --- | --- | --- |
| 短期记忆 | 当前对话的任务目标、条件、近期消息、工具结果和未完成事项 | 连续交流时接得上，知道当前正在处理什么 |
| 长期记忆 | 用户背景、稳定偏好、长期目标、纠正和约定 | 换一个会话仍能理解你的背景与习惯 |
| 历史记录 | 过去的对话、任务过程和实际执行结果 | 找回当时的讨论、决定和结果 |

例如，“喜欢简洁回答”属于长期记忆；“上次为什么选择 A 方案”应查历史。长期记忆保存精华，历史保留可回查的细节。用户提供的具体资料——文档正文、参考内容、项目细节记录——属于个人资料库（第 8 节），不写入长期记忆；长期记忆只保留精简的用户背景、稳定偏好与持续约定。

过去讨论过的想法不代表已经执行，Agent 的历史总结不代表用户最终决定。

### 2.1 短期记忆：保持当前任务上下文

短期记忆是 Agent 处理当前对话时使用的上下文，不另设一个供用户编辑的“短期记忆文件”。

- 连续交流时理解指代。例如先说“修改这段介绍”，再说“再短一点”，Agent 能继续修改同一段内容。
- 保留当前目标、用户补充的条件、已作出的决定、工具结果，以及等待补充或尚未完成的事项。
- 上下文过长时，在内部整理较早内容，保留继续任务所需的信息；完整聊天记录仍在页面中保留，也能通过历史检索找回。
- 整理后的摘要不能将提议变成决定、将尝试变成成功；需要精确细节时回查原记录。
- 刷新页面或重新打开原对话后，能够接着已保存的上下文继续。新建会话开始新的短期上下文，不自动带入上一任务的全部内容；需要时读取长期记忆或检索历史。

短期记忆中的一次性要求不会因上下文整理自动变成长期偏好。

### 2.2 常驻上下文与按需检索

Agent 每轮能用的上下文有限，个人信息却会一直增长。因此个人上下文分成三层，由程序在每轮开始前装配常驻的两层：

| 层 | 是什么 | 是否每轮带给 Agent | 作用 |
| --- | --- | --- | --- |
| 长期记忆 | 内容本身：背景、偏好、约定 | 是，全文 | Agent 直接照着做 |
| 资料目录 | 指针：有哪些资料、各讲什么、在哪 | 是，有容量上限 | Agent 据此决定要不要去查 |
| 资料正文 | 具体内容 | 否 | 需要时检索或读取 |

判断一条信息放记忆还是放资料，只问一个问题：**Agent 这一轮没看到它，会不会在用户没提起的情况下做错？** 会做错的（如“回答先给结论”“内部会议默认 45 分钟”）放记忆；只是被问到时答不上来的（如验收代号、办公室位置、截止日期）放资料。内容长短不是标准：一条很短的事实照样是资料。资料目录是资料的一部分，不能代替记忆——目录里列着一份讲回答风格的资料，Agent 未必会去读，偏好就不会生效。

历史对话、邮件与日程和资料正文一样按需检索，不自动带入。

- 常驻内容都有容量上限：长期记忆超出时按第 3.4 节提示整理；资料目录超出时按目录合并、最近更新优先（`kb-spec.md` 第 4.3 节），列不下的仍可检索。
- 记忆与资料只负责保存、整理和提供信息，不执行发送邮件、创建日程等外部操作，也不替代用户授权。
- 首版不在每轮回答前自动预先检索历史或资料，由 Agent 自行决定是否检索；实测发现经常漏查时，再考虑增加回答前的预检索。

## 3. 长期记忆

### 3.1 形成记忆

记忆有两条形成路径：每个用户消息轮的专用记忆判断，以及后台定期回顾（第 3.5 节）。用户也可以在管理页面直接编辑记忆文档。

每个用户消息轮都经过一次专用记忆判断：一次独立于主回答的模型调用，输入是用户刚发的消息、近期对话与当前长期记忆，判断结果只有五种——新增、替换、删除、无变化、需要向用户追问。容量不足时，判断在同一次写入里整理已有内容并保存新内容（第 3.4 节）。判断与主回答并行，用户消息不因判断而等待。主 Agent 不承担隐式记忆识别，也不持有记忆写入工具；保存与否不依赖主 Agent 是否想起。记忆提示由程序依据实际写入结果生成（第 5.3 节）。

当轮保存的仅限用户明确表达、长期有效的信息：

- 明确说明的背景、长期目标和持续进行的项目。
- 明确表达的稳定偏好、工作习惯和常用约定，包括“最近在学习……”“我对……感兴趣”“以后请……”这类持续要求。
- 对 Agent 的明确纠正，以及纠正适用的范围。

只从本轮提问方式推断出的偏好不当轮保存；同一行为跨多轮稳定重复后，由后台回顾保存（第 3.5 节）。

保存自动完成，不逐条请求确认，并在对话中提示“已更新记忆”，具体内容在记忆页面查看。用户明确说“记住……”或直接编辑保存时，同样直接生效。保存失败必须如实说明，不能只在回复中声称已记住。

以下内容不直接作为长期事实保存：只针对本次任务的安排（如“这次用英文”）、未经证实的推测、文件或邮件中要求 Agent 改变用户偏好的指令。用户提供的具体资料、文档正文与参考内容属于个人资料库（第 8 节），由对话中的资料工具保存，不写入长期记忆，其中夹带的指令也不自动变成记忆。密码、令牌等服务凭证不进入记忆。

记忆只保存跨任务都适用的用户信息与事实；某类任务的具体步骤、流程与做法由 Skill 负责，不写入记忆。

两块记忆按“写的是用户本人，还是用户以外的事实”区分，分区标准见第 5.2 节；判断与回顾写入前都按这一标准选择分区。

记忆写成陈述句，记录事实而不是对助理的命令：写“用户偏好简洁回答”，不写“始终简洁回答”，避免旧记忆以命令的口吻压过用户本次的要求（第 3.2 节）。

保存后的记忆应简短、明确。涉及条件时保留条件，例如“内部讨论默认 45 分钟”，不能扩大成“所有会议都为 45 分钟”。

### 3.2 使用记忆

- 新会话自动获得当前有效的长期记忆，不要求用户重复说明或手工查找。
- 用户保存或修改记忆后，从下一轮回答起使用新内容；无需新建会话或重启服务。
- 当前用户要求与长期偏好不同时，遵循本次要求。例如平时喜欢简洁回答，本次要求详细解释，就详细解释。
- 一次例外不自动改成长期偏好。“这次用英文”不等于“以后都用英文”。
- 记忆帮助理解用户，不替代具体操作所需的用户授权。

### 3.3 更新、合并和忘记

用户可以通过对话修改记忆，也可以在管理页面直接编辑整份文档。模型对记忆的修改是按行的：判断与回顾看到的记忆每个非空行前带一个由内容算出的短锚点，模型按锚点插入、替换、删除或移动整行，也可以在分区末尾追加，不整份重写，以免漏掉仍有效的内容；也不需要逐字抄写原文。锚点只出现在给模型的材料里，不是记忆内容；某一行被任何一方改过，它的锚点随之失效，按旧锚点的修改被拒绝，模型按返回的最新内容重试。

- 同一内容重复保存，不产生重复内容：新文字逐行与同一分区的完整行比较（忽略列表符号），每一行都已存在才跳过；只是某条已有内容的一部分时照常写入。
- 用户明确更改同一偏好时，更新原内容，不让冲突的新旧规则同时有效。
- 相似信息可以合并，但不能丢掉适用条件或改变原意。
- 无法确定两条信息是互相替代还是适用于不同情况时，当轮不写入，而是向用户提出一句具体的确认问题；用户澄清后的下一轮再执行修改。
- “忘记”即从长期记忆中删除对应内容；原对话仍保留，提示中说明这一点。记忆不做版本管理，误改或误删时由用户在对话中说明（例如“改回去”），或在管理页面重新编辑；对话里的记忆提示展示了原内容，可作为依据。

删除的记忆不再提供给 Agent，也不能仅因为原对话仍存在就自动重新保存。用户明确要求回顾原对话时，可以返回原记录，但应区分历史内容与当前有效偏好。

### 3.4 保持记忆精简

长期记忆有容量上限，用户可以查看已用容量。整篇资料和完整对话不塞进长期记忆；整篇资料改存到个人资料库（第 8 节）。

整理交给模型：每轮判断与后台回顾都能看到每块记忆的已用与上限字数，要保存的内容放不下时，在同一次写入里合并重复或相近的内容、精简措辞并加入新内容（一次写入可以同时改两个分区，整体生效，容量按每个分区的最终结果检查），不留下整理了一半的中间状态；整理产生的修改与删除都在对话中提示。整理不得删除仍有效且含义不同的信息，也不能去掉或扩大适用条件；实在腾不出空间时明确提示保存失败，不能静默截断、丢弃现有内容，或在保存失败后声称已经记住。用户也可以在管理页面查看容量并手动整理。

文件被直接编辑到超出容量时仍照常读取和使用；此后只接受让它变小的修改，新增会被拒绝，直到整理回上限以内。

当前采用与 Hermes 相同的默认容量：`USER.md` 1375 个 Unicode 字符，`MEMORY.md` 2200 个字符。

### 3.5 后台记忆回顾

每轮专用记忆判断是第一条发现路径，负责用户单轮明确表达的信息；后台记忆回顾是第二条，负责单轮看不出来、连续多轮后才稳定下来的偏好与习惯，同时整理长期记忆。两条路径共用同一份长期记忆。

- 每个任务内，每完成 5 个用户消息轮自动回顾一次：独立的一次性模型会话重读这段对话，把值得跨会话保留的用户信息补进长期记忆。回顾只覆盖自上次已完成回顾以来的新对话。
- 回顾同时整理长期记忆：把放错分区的内容移到正确分区（一次写入完成，目标分区放不下时整体不生效，内容仍留在原分区），把相关内容归到一起，合并重复或相近的内容、精简措辞，对话中有明确依据表明某项已经过时或失效时更新或删除它，容量接近上限时优先整理。没有明确依据时不改动已有内容，不删除仍有效且含义不同的信息，不去掉或扩大适用条件。回顾不向用户追问。
- 回顾保存前对照当前长期记忆去重：即时判断已写入的内容不会因回顾重复出现。
- 回顾独立于用户对话运行：不占用任务的对话轮，不出现在任务列表。新增不通知；修改、删除与移动以程序提示写入该任务时间线（挂在回顾覆盖的最后一轮上）。用户消息永远不等回顾完成。
- 服务重启时，正在执行的回顾标记为中断；已完成轮数的计数不受影响，下一条消息完成后回顾自动重新触发，无需人工干预。
- 提供手动触发入口：立即对整个任务历史做一次回顾，不受 5 轮间隔限制；同一任务已有未完成的回顾时不重复登记。
- 纯闲聊或没有新稳定信息的对话回顾后不产生任何记忆写入。
- 周期间隔可通过配置调整；自动回顾可整体关闭，关闭只影响自动触发，手动入口不受限。

## 4. 历史对话与任务回忆

### 4.1 查找过去的内容

用户可以通过关键词或自然语言查找历史，并用时间、任务或对话缩小范围。例如：“上个月讨论研究计划时，你给了哪些修改意见？”

可检索的内容包括用户与 Agent 的消息，以及已保存的任务操作和结果。找到片段后，Agent 能继续读取前后文，避免只凭一句话解释整段讨论。历史对话属于按需检索，不自动带入每轮上下文（第 2.2 节）。

### 4.2 回答符合历史记录

- 回答内容与实际查到的记录一致；回答下方不附来源或引用列表。
- 区分提议、用户决定、执行尝试和实际执行结果。
- 没有执行记录时，不把“准备发送”说成“已经发送”。
- 找不到匹配记录时，说明未找到，不用长期记忆推测当时具体说过什么。
- 检索历史不自动把所有命中内容重新保存为长期记忆。

刷新页面、重启服务或新建会话后，已保存的历史仍可检索。

实现约定：

- Agent 有两个只读工具，所有轮次可用：`history_search`（关键词，可选起止日期，默认排除当前任务，新到旧返回任务、条目、说话方、时间与片段）与 `history_read`（读取某条记录前后各若干条原文，邮件草稿附最新内容、状态与执行结果）。
- 可检索的是已结束轮次里的用户消息、Agent 回答、程序提示与邮件草稿（收件人、主题、正文与状态）；进行中的轮次暂不可检索，错误条目不检索。
- 检索用与资料库相同的全文检索方式，全部关键词命中才算命中；日期按本机时区的自然日。
- 索引是可从时间线重建的派生数据，检索前增量同步：新条目补入，草稿改版或执行状态变化后重写；删除任务时一并清除。

## 5. 查看和管理记忆

### 5.1 三个使用入口

| 入口 | 呈现内容 | 用户操作 |
| --- | --- | --- |
| 当前对话 | 消息、可展示的工具结果和任务进度 | 连续提问、补充条件、继续当前任务 |
| 长期记忆 | “关于你”和“事实与约定”两个分区 | 查看容量，直接编辑整份内容 |
| 历史对话 | 历史会话列表、搜索结果与原消息 | 查找过去的讨论，打开命中位置和前后文 |

短期记忆体现在当前对话能接续交流，不提供单独的短期记忆编辑页面。上下文压缩不会删除页面上已保存的消息。

### 5.2 长期记忆页面与文件

长期记忆使用两个可直接阅读和编辑的 Markdown 文件，每个文件是一份完整文档，写法不限（段落、列表、小标题），不按条分隔；页面展示对应内容，文件修改与页面编辑作用于同一份记忆。

| 页面分区 | 对应文件 | 内容 |
| --- | --- | --- |
| 关于你 | `USER.md` | 用户本人：身份、长期目标、学习与研究方向、兴趣、沟通与表达偏好、工作习惯、对助理的总体期望。例：“用户正在学习 Hermes Agent 的设计”“用户偏好先给结论再解释” |
| 事实与约定 | `MEMORY.md` | 用户以外、跨任务都成立的事实与约定：常用账号、日历、联系人的事实，固定的安排规则，使用各项服务时确认过的经验。例：“‘工作’日历用于内部会议”“内部会议默认 30 分钟”；可以查的项目信息、术语资料放资料库 |

页面把两份文档渲染成 Markdown 展示，例如：

> **关于你**
>
> - 用户默认使用简体中文。
> - 用户偏好先给结论，再解释原因。
>
> **事实与约定**
>
> - 内部讨论默认 45 分钟。

两个文件只保存当前有效的长期记忆；完整历史对话与短期上下文不塞入这两个文件。记忆不做版本管理，也不记录出处：内容可查看、可修改即可。

用户能够：

- 查看两个分区渲染后的完整内容与已用容量（超出上限时明确提示）。
- 在渲染后的内容上直接编辑（所见即所得），有改动时保存或放弃；输入时容量实时更新，超限且变大的内容不能保存。修改从下一轮起生效。
- 有未保存的修改时关闭或刷新页面会提醒。
- 页面打开后记忆被判断、回顾或编辑器改过时，保存不会覆盖，页面保留本次输入，提示并让用户重新载入。

用户直接修改 `USER.md` 或 `MEMORY.md` 后，下一轮使用修改后的有效内容；不能只在界面中可编辑、实际文件变化却不生效。

页面地址为 `/memory`，入口在电脑侧栏与手机底部 tab；电脑和手机浏览器均能完成查看与修改。删除后的内容不再作为有效记忆注入；历史检索仍可按用户要求找回原讨论，并说明该偏好已经不在记忆中。

### 5.3 对话中的记忆变更提示

记忆提示由程序依据实际写入结果生成，与主回答分开展示；主 Agent 不复述记忆保存结果。变更成功后不在对话中复述具体内容，并提供“查看记忆”入口：

- 新增、修改、忘记与换分区：同一轮只提示一次“已更新记忆”。
- 内容已存在：“这条内容已经在记忆里。”不重复保存。
- 需要澄清：展示判断步骤给出的确认问题，例如“想确认：你说的是‘用户偏好先给结论’这条，还是‘推导过程要完整’这条？”；用户澄清前不做任何写入。
- 后台整理：修改、删除或换分区实际生效时，同一次整理只提示一次“已整理记忆”；只新增不提示。

提示依据实际保存结果生成。保存失败时明确展示失败与原因，未成功的操作不能显示为已完成；判断失败后又重试并保存成功的（例如容量不足后先整理、锚点失效后按最新内容重做），只看这次判断里最后一次写入的结果，不再提示前面的失败。后台回顾的失败不提示，整次不生效。点击入口打开长期记忆页面。

### 5.4 历史搜索

用户可以浏览历史会话列表、搜索历史，也可以直接在当前对话中询问过去的事情。

- 搜索结果显示对话标题、说话方、时间和命中片段，从新到旧排列；点击后打开原对话并定位到命中消息（短暂高亮），可以继续查看前后文，而不只是打开会话首页。
- 入口：电脑侧栏“任务”标题旁的搜索按钮，手机任务列表上的“搜索对话”；搜索页地址为 `/search?q=`，接口为 `GET /api/history/search`。
- 在对话中询问过去的事情时，Agent 检索历史后直接回答，回答下方不附来源或引用列表。

## 6. 完整使用示例

### 6.1 记住、修正和忘记

1. 用户说：“以后先给我结论，再解释原因。”
2. Agent 保存偏好，并提示“已更新记忆”。
3. 用户新建会话提问，Agent 应用这一偏好。
4. 用户说：“以后改成先解释推导。”Agent 更新原偏好，提示“已更新记忆”。
5. 下一轮使用新偏好，不同时遵循旧偏好。
6. 用户说：“忘记这个回答顺序偏好。”Agent 从记忆中删除，提示“已更新记忆”。
7. 新会话不再自动应用该偏好，也不因检索到原对话就重新保存它。

### 6.2 回忆过去并继续任务

用户说：“我们上次为什么放弃 A 方案？按最后的决定继续。”

Agent 查找相关历史，读取必要上下文，解释有记录支持的原因，并区分讨论过的方案与最终决定。找到明确决定后继续处理；有多个候选或没有最终决定时，说明缺失信息并询问。

以上为验收示例，不要求每个任务固定经过同样的工具调用步骤。

## 7. 验收标准

以下均为应验证的产品行为，不代表已经实现或通过测试。

| 编号 | 用户操作或情境 | 可观察的结果 |
| --- | --- | --- |
| S1 | 先要求修改一段介绍，再说“再短一点” | 接续修改同一内容，保留本次已明确的条件 |
| S2 | 长对话触发上下文整理后继续任务 | 保留目标、决定、结果和未完成事项；页面原消息仍完整，精确细节可回查 |
| S3 | 刷新后继续原对话，再新建会话 | 原对话可继续；新会话不自动沿用上个任务的一次性要求 |
| M1 | 要求记住“先给结论”，再新建会话提问 | 无需重复说明，新会话按偏好回答；可查看已保存内容 |
| M2 | 用户在普通对话中明确表达长期有效的偏好 | 当轮自动保存（不依赖主回答是否提及），对话提示“已更新记忆”，实际内容可在记忆页面查看；不要求逐条确认 |
| M3 | 将同一偏好改成“先解释推导” | 下一轮采用新偏好；旧内容不再同时有效；记忆页面显示更新后的内容 |
| M4 | 平时用中文，本次要求英文 | 本次用英文；长期语言偏好不被改写 |
| M5 | 再次表达同一偏好 | 不产生重复内容 |
| M6 | 要求忘记某条记忆，再新建会话 | 不自动应用，也不从原对话自动恢复该记忆；原对话仍可查看 |
| M7 | 记忆接近上限时再保存新偏好 | 模型先合并或精简已有内容再保存，整理内容以提示展示；腾不出空间时明确失败；仍有效且含义不同的内容不丢失 |
| M8 | 记忆写入失败 | 明确展示失败与原因，不声称记忆已生效 |
| M9 | 用户直接编辑记忆文件，或在管理页面修改 | 下一轮读取正确的当前内容 |
| M10 | 任务内完成 5 个用户消息轮 | 后台回顾自动执行：长期记忆出现应保留内容，且不重复保存即时判断已写入的内容；只新增时时间线与任务列表无可见变化，合并、更新、删除或移动已有内容时时间线出现“整理记忆”提示 |
| M11 | 对任意任务手动触发记忆回顾 | 立即执行覆盖全任务的回顾，不受间隔限制；任务不存在时明确报错 |
| M12 | 服务在回顾执行中重启，随后再发一条消息 | 重启时回顾标记为中断且无残留；下一条消息完成后回顾自动重新触发并完成 |
| M13 | 修改偏好但指向不明确（多条候选或改法有多种理解） | 当轮不写入；展示一句具体的确认问题；用户澄清后的下一轮才执行修改 |
| M14 | 任意用户消息轮 | 专用记忆判断与主回答并行：回答不被判断阻塞；记忆提示由程序依据实际写入结果追加，主 Agent 不复述保存结果 |
| M15 | 先说一条个人偏好，再说一条团队会议约定 | 偏好写入“关于你”，会议约定写入“事实与约定”；两者都写成陈述句 |
| C1 | 长期记忆与资料库持续增长后开始新会话 | 常驻内容保持在容量上限内；资料与历史细节不自动塞入，Agent 需要时再检索 |
| H1 | 查找过去讨论中的决定 | 找到真实记录，结论与记录一致，回答不附来源列表 |
| H2 | 历史中只有操作提议，没有成功结果 | 不报告操作已完成 |
| H3 | 重启服务后查找过去的讨论 | 已保存的历史仍可检索 |
| H4 | 没有匹配记录 | 明确说明未找到，不编造历史 |
| U1 | 在手机与电脑查看与修改记忆 | 两端均可完成，无需操作命令行 |
| U2 | 打开长期记忆页面并编辑两个分区 | “关于你”对应 `USER.md`，“事实与约定”对应 `MEMORY.md`；页面渲染的 Markdown 与文件内容一致，直接编辑后文件随之更新；页面显示已用容量 |
| U3 | 新增、修改、忘记一条记忆 | 对话提示“已更新记忆”，不复述具体内容，可从提示打开长期记忆页面 |
| U4 | 搜索历史并点击结果 | 显示标题、时间与片段，打开原对话并定位到命中消息，可查看前后文 |
| U5 | 页面打开期间记忆被判断或编辑器改过，再在页面保存 | 保存被拒绝并提示重新载入，不覆盖他人修改 |
| E1 | 完成第 6.1 节全部步骤 | 保存、跨会话应用、更新和忘记形成完整链路 |
| E2 | 完成第 6.2 节任务 | 历史依据真实，最终决定与讨论内容区分准确 |

验收必须覆盖真实模型对记忆的应用、短期上下文保持与压缩后的任务接续、持久保存后跨会话读取、历史检索与界面定位。仅测试文件读写或使用固定模拟回答，不足以证明上述完整能力。

## 8. 与个人资料库的分工

个人资料库（Personal KB）与 Memory 的区别在于 Agent 怎么用它：Memory 是“不查就必须生效”的内容，全文常驻；资料是“知道有它、需要时再查”的内容，每轮常驻的只是资料目录（第 2.2 节）。资料库的产品行为以 `docs/kb-spec.md` 为准，存储与工具字段以 `docs/contracts/personal-kb.md` 为准，本文不重复定义。

分工边界：

- 长期记忆只保留不查就必须生效的精简背景、稳定偏好、长期目标、纠正与持续约定；用户提供的具体资料——笔记、文档正文、参考内容、项目细节、术语资料——保存到资料库，不写入 `USER.md`/`MEMORY.md`。
- 两边都沾的信息拆开放：影响很多回答的背景（如“张老师是我的导师”）放记忆，相关细节（联系方式、沟通记录）放资料。
- 目标与项目的分工：长期记忆只保留一句话的长期目标；项目的进展、决定与细节由资料库的主题页整理（`kb-spec.md` 第 8 节）。
- 两条路径在对话中展示方式不同：偏好与背景由每轮专用记忆判断写入，并提示“已更新记忆”；资料由对话中的资料工具保存（包括 Agent 主动保存），程序展示资料的保存位置，不复用记忆提示。
- 涉及资料中的具体事实时以资料原文为依据：先检索、再读取原文后回答；记忆提供的是偏好与背景，不作为资料事实的依据，检索不到时如实说明。回答不展示来源。
- 用户意图不明确（究竟想长期记住一个偏好、还是想保存一份资料）时，Agent 先问清楚再操作。
- 用户给出的资料正文及其中夹带的指令不自动变成长期记忆。

本阶段不把已有长期记忆里的旧资料批量迁移进资料库；迁移留待资料库后续阶段逐条核对后再做。

## 9. 与 Hermes 的异同

沿用 Hermes 的做法：

- 两份容量受限的长期记忆：`USER.md` 记用户本人（1375 个字符），`MEMORY.md` 记用户以外的事实与约定（2200 个字符）；内容写成陈述句。
- 模型按行锚点编辑记忆；容量不足时在一次写入里整理并保存，不自动截断。
- 长期记忆与历史对话检索分开；后台定期回顾补充与整理记忆。

不同之处：

- 每份记忆是一份完整的 Markdown 文档，不按条分隔；页面以渲染后的 Markdown 直接编辑。
- 保存后从下一轮起生效；Hermes 在会话开始时加载固定快照。
- 即时记忆由每个用户消息轮的专用判断完成，与主回答并行，提示由程序依据实际写入结果生成；Hermes 由 Agent 自行决定是否调用记忆工具。
- 回顾每 5 个已完成用户消息轮触发；新增不提示，修改、删除与移动提示。
- 记忆不做版本管理，“忘记”即删除。

常驻上下文与按需检索分开、控制预算的思路参考 OpenHuman（第 2.2 节，取舍见 `kb-spec.md` 第 11 节）；它的独立目标文件与数据块出处不采用。

本规格不包含 Skill 的创建与审核，也不要求知识图谱或第三方记忆服务；邮件发送、日程创建等功能不由本文定义。验收以本文写明的产品行为为准，不随上游实现变化。
