# Pebble 记忆功能规格

本文说明用户能得到什么，不限定实现；文件格式、工具与接口见 `contracts/memory.md`，个人资料库见 `kb-spec.md`（分工见第 7 节）。

## 1. 目标

Pebble 在长期使用中了解用户，并能找回过去的讨论：不必每次重复背景，也不必记住信息出现在哪次对话。用户直接说“记住……”“上周为什么放弃那个方案？”“忘记……”即可，用哪类信息由 Agent 判断。

## 2. 三类信息

| 类别 | 内容 | 用法 |
| --- | --- | --- |
| 短期记忆 | 当前对话的目标、条件、决定、工具结果与未完成事项 | 当前任务的上下文 |
| 长期记忆 | 用户背景、稳定偏好、长期目标、纠正与约定 | 每轮全文带入 |
| 历史记录 | 过去的对话、任务过程与执行结果 | 需要时检索 |

具体资料（文档正文、参考内容、项目细节）属于个人资料库，不写入长期记忆。

### 2.1 短期记忆

- 连续对话能理解指代，保留目标、条件、决定、结果与待办。
- 上下文过长时在内部整理较早内容：摘要不能把提议写成决定、把尝试写成成功，精确细节回查原记录；页面上的完整消息不受影响。
- 刷新或重开原对话可以接着做；新会话从新的短期上下文开始，需要时读长期记忆或检索历史。
- 一次性要求不会因整理而变成长期偏好。

### 2.2 常驻与按需

每轮只带入容量受限的常驻材料：长期记忆全文与资料目录（资料的指针）。资料正文、历史对话、邮件与日程都按需检索；首版不在回答前预先检索。

放记忆还是放资料，只问一个问题：**Agent 这一轮没看到它，会不会在用户没提起时做错？** 会做错的放记忆（如“回答先给结论”“内部会议默认 45 分钟”），只是被问到答不上来的放资料（如验收代号、截止日期），与内容长短无关。

记忆与资料只提供信息，不执行外部操作，也不替代用户授权。

## 3. 长期记忆

### 3.1 形成记忆

两条路径写入，用户也可以直接编辑：

- **每轮记忆判断**：每个用户消息轮与主回答并行运行一次独立的模型调用，结果为新增、替换、删除、无变化或追问之一。主 Agent 不写记忆。
- **后台回顾**（第 3.5 节）：补上跨多轮才稳定的偏好，并整理记忆。

当轮只保存用户明确表达、长期有效的内容：背景、长期目标与持续项目；稳定偏好、习惯与持续要求（如“以后请……”“最近在学……”）；对 Agent 的纠正及其适用范围。只从提问方式推断出的偏好留给后台回顾。

不保存：一次性安排（“这次用英文”）、未经证实的推测、文件或邮件里要求改变偏好的指令、资料正文、凭证，以及某类任务的具体做法（属于 Skill）。

写法：陈述事实而不是命令（写“用户偏好简洁回答”，不写“始终简洁回答”），保留适用条件、不扩大。按“用户本人 / 用户以外的事实”分区（第 5.2 节）。

保存自动完成，不逐条确认；失败必须如实说明。

### 3.2 使用记忆

- 新会话自动带入当前记忆；保存或修改后从下一轮起生效，无需新建会话或重启。
- 本次要求与长期偏好冲突时按本次要求，一次例外不改长期偏好。

### 3.3 更新、合并和忘记

- 模型按行修改记忆，不整份重写；基于过期内容的修改被拒绝并重做。
- 同一内容不重复保存；同一偏好被更改时替换原内容，新旧规则不并存。
- 合并相似内容时不丢条件、不改原意；拿不准是替换还是并存时，当轮不写入，先问一句具体的确认问题。
- “忘记”即删除，原对话仍保留，也不会因原对话还在而自动恢复。记忆不做版本管理，提示也不复述内容：误改时由用户说明要恢复的内容，或在页面重新编辑。

### 3.4 保持精简

`USER.md` 上限 1375 个 Unicode 字符，`MEMORY.md` 2200 个（与 Hermes 相同）。放不下时，判断或回顾在同一次写入里合并、精简已有内容再加入新内容，整体生效；不能删掉仍有效且含义不同的信息，腾不出空间就明确失败，不截断、不声称已记住。文件被直接编辑到超限时照常使用，此后只接受让它变小的修改。

### 3.5 后台回顾

- 每个任务每完成 5 个用户消息轮，由独立会话回顾自上次以来的新对话：补充值得保留的信息，并整理记忆（移回正确分区、归并、精简；有明确依据时才更新或删除）。不向用户追问，不重复即时判断已写入的内容。
- 不占对话轮、不进任务列表，用户消息不等它。
- 重启时进行中的回顾记为中断，下一条消息完成后自动重跑。
- 手动入口对整个任务历史回顾一次，不受间隔限制；同一任务不会同时有两次未完成的回顾。
- 间隔可配置，自动回顾可关闭，不影响手动入口。

## 4. 历史对话

用户可以用关键词或自然语言查找过去的讨论，并按时间缩小范围；可检索对话消息与已保存的操作和结果，找到后能读前后文。重启、刷新或新建会话后仍可检索。

回答必须与记录一致，不附来源；区分提议、决定、尝试与实际结果（没有发送记录不说“已发送”）；找不到就说找不到，不用记忆推测；找回已被忘记的偏好时说明它已不在记忆中；检索结果不自动写入记忆。

工具与接口见 `contracts/memory.md` 第 3 节。

## 5. 界面

### 5.1 入口

当前对话用于接续交流，长期记忆页面用于查看和编辑两个分区，历史搜索用于找回过去的讨论。没有单独的短期记忆页面，上下文压缩不删除页面上的消息。

### 5.2 长期记忆页面与文件

| 分区 | 文件 | 写什么 |
| --- | --- | --- |
| 关于你 | `USER.md` | 用户本人：身份、目标、学习与研究方向、兴趣、表达偏好、工作习惯、对助理的期望 |
| 事实与约定 | `MEMORY.md` | 用户以外、跨任务成立的事实与约定：账号、日历、联系人的事实，固定安排规则，使用服务时确认过的经验 |

- 每个文件是一份完整的 Markdown 文档，写法不限；页面与文件是同一份内容，直接改文件下一轮同样生效。
- 页面地址 `/memory`，电脑与手机都能查看渲染后的内容与已用容量，并所见即所得地编辑；超限且变大的内容不能保存。
- 有未保存修改时离开会提醒；页面打开后记忆被别处改过时，保存被拒绝并提示重新载入。

### 5.3 对话中的记忆提示

由程序按实际写入结果生成，主 Agent 不复述；提示不带具体内容，附“查看记忆”入口。

- 当轮有新增、修改、删除或换分区：提示一次“已更新记忆”。
- 内容已存在：“这条内容已经在记忆里。”
- 需要澄清：展示确认问题，澄清前不写入。
- 保存失败：展示失败与原因；同一次判断里重试成功的，只看最后一次结果。
- 后台回顾：有修改、删除或换分区时提示一次“已整理记忆”；只有新增或回顾失败时不提示。

### 5.4 历史搜索

入口在电脑侧栏“任务”旁的搜索按钮与手机任务列表的“搜索对话”，页面为 `/search?q=`。结果从新到旧显示标题、说话方、时间与片段，点击打开原对话并定位、高亮命中消息。

## 6. 验收

本文每条规则都是验收项。此外必须用真实模型走通以下场景；只测文件读写或使用固定的模拟回答不算通过。

1. **记住、修正、忘记**：说“以后先给结论” → 提示已更新 → 新会话按此回答 → 改成“先解释推导” → 下一轮只按新偏好 → “忘记这个偏好” → 新会话不再应用，也不从原对话恢复。
2. **回忆并继续**：“我们上次为什么放弃 A 方案？按最后的决定继续。” → 依据真实记录说明原因，区分讨论与决定；没有明确决定时追问。
3. **长对话压缩**：上下文整理后继续任务，目标、决定、结果与待办不丢，页面原消息完整。
4. **后台回顾**：完成 5 轮后自动回顾且不重复保存；回顾中途重启，下一条消息完成后自动重跑。
5. **分区**：先说个人偏好、再说团队会议约定，两条分别写入两个分区，都是陈述句。
6. **两端界面**：电脑与手机上查看、编辑记忆，搜索历史并定位到命中消息。

## 7. 与个人资料库的分工

- 记忆只放不查就必须生效的精简内容；笔记、文档、项目细节与术语放资料库。
- 两边都沾的拆开放：影响很多回答的背景（“张老师是我的导师”）放记忆，细节放资料。
- 长期记忆只留一句话的长期目标，项目进展由资料库的主题页整理。
- 资料写入的提示显示保存位置，不复用记忆提示。
- 回答资料里的事实以原文为准，先检索再读取；记忆不作为资料事实的依据。
- 分不清用户想记偏好还是存资料时先问。
- 本阶段不把旧记忆里的资料迁移到资料库。

## 8. 参考与取舍

沿用 [Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)：两份容量受限的记忆、陈述句、按行编辑、放不下时整理而不截断、长期记忆与历史检索分开、后台回顾。不同之处：每份记忆是一份完整的 Markdown 文档而非条目列表；修改从下一轮起生效，而不是会话开始时的固定快照；即时记忆由每轮专用判断完成，而不是由 Agent 自己决定调用；记忆不做版本管理。

常驻与按需分开的思路参考 [OpenHuman](https://github.com/tinyhumansai/openhuman/blob/main/gitbooks/features/obsidian-wiki/memory-tree.md)（取舍见 `kb-spec.md` 第 10 节），不采用它的独立目标文件与数据块出处。
