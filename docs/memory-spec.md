# Pebble 记忆功能规格

状态：功能规格草案。长期记忆文件、写入工具、逐轮加载与本地 Git 历史已实现；管理页面、历史检索与恢复尚未实现。已确认：主动记忆自动保存并展示内容；“忘记”默认停止使用并保留历史。个人资料库尚未纳入本规格，见第 8 节。

本文描述用户能够获得的功能，不限定数据库、检索算法或模型实现。本文依据本次讨论重新定义 Memory 相关范围。整体确认后，应将对应范围同步到 `v1-spec.md`、设计与接口文档，避免出现两套有效规则。本文不是已实现功能清单。

## 1. 产品目标

让 Pebble 在长期使用中了解你，并能找回过去的讨论。你不必每次聊天都重复背景，也不必记住信息出现在哪次对话里。

你可以直接说：

- “记住，我希望先看结论，再看解释。”
- “上周我们为什么放弃那个方案？”
- “参考上次讨论的意见，继续完善我的研究计划。”
- “把我刚才说的偏好改掉。”
- “忘记我偏好英文回答这件事。”

Agent 按问题自行选择需要的信息。用户不需要先选择搜索工具或记忆类型。

## 2. 三类信息分别做什么

| 类别 | 保存什么 | 用户获得什么 |
| --- | --- | --- |
| 短期记忆 | 当前对话的任务目标、条件、近期消息、工具结果和未完成事项 | 连续交流时接得上，知道当前正在处理什么 |
| 长期记忆 | 用户背景、稳定偏好、长期目标、纠正和约定 | 换一个会话仍能理解你的背景与习惯 |
| 历史记录 | 过去的对话、任务过程和实际执行结果 | 找回当时的讨论、决定和结果 |

例如，“喜欢简洁回答”属于长期记忆；“上次为什么选择 A 方案”应查历史。长期记忆保存精华，历史保留可回查的细节。

过去讨论过的想法不代表已经执行，Agent 的历史总结不代表用户最终决定。

### 2.1 短期记忆：保持当前任务上下文

短期记忆是 Agent 处理当前对话时使用的上下文，不另设一个供用户编辑的“短期记忆文件”。

- 连续交流时理解指代。例如先说“修改这段介绍”，再说“再短一点”，Agent 能继续修改同一段内容。
- 保留当前目标、用户补充的条件、已作出的决定、工具结果，以及等待补充或尚未完成的事项。
- 上下文过长时，在内部整理较早内容，保留继续任务所需的信息；完整聊天记录仍在页面中保留，也能通过历史检索找回。
- 整理后的摘要不能将提议变成决定、将尝试变成成功；需要精确细节时回查原记录。
- 刷新页面或重新打开原对话后，能够接着已保存的上下文继续。新建会话开始新的短期上下文，不自动带入上一任务的全部内容；需要时读取长期记忆或检索历史。

短期记忆中的一次性要求不会因上下文整理自动变成长期偏好。

## 3. 长期记忆

### 3.1 形成记忆

用户可以在对话中明确要求记住某件事，也可以在管理界面直接新增记忆。

Agent 能识别对未来有帮助的信息，包括：

- 用户明确说明的背景、长期目标和持续进行的项目。
- 用户稳定的表达偏好、工作习惯和常用约定。
- 用户对 Agent 的纠正，以及纠正适用的范围。

Agent 自主识别值得长期保留的信息后自动保存，不逐条请求确认，并在对话中展示实际保存内容。用户明确说“记住……”或直接编辑保存时，同样直接生效。保存失败必须如实说明，不能只在回复中声称已记住。

以下内容不直接作为长期事实保存：只针对本次任务的安排、未经证实的推测、文件或邮件中要求 Agent 改变用户偏好的指令。密码、令牌等服务凭证不进入记忆。

保存后的记忆应简短、明确。涉及条件时保留条件，例如“内部讨论默认 45 分钟”，不能扩大成“所有会议都为 45 分钟”。

### 3.2 使用记忆

- 新会话自动获得当前有效的长期记忆，不要求用户重复说明或手工查找。
- 用户保存或修改记忆后，从下一轮回答起使用新内容；无需新建会话或重启服务。
- 当前用户要求与长期偏好不同时，遵循本次要求。例如平时喜欢简洁回答，本次要求详细解释，就详细解释。
- 一次例外不自动改成长期偏好。“这次用英文”不等于“以后都用英文”。
- 记忆帮助理解用户，不替代具体操作所需的用户授权。

### 3.3 更新、合并和忘记

用户可以通过对话或管理界面新增、编辑、删除记忆。

- 同一条内容重复保存，不产生重复条目。
- 用户明确更改同一偏好时，更新原条目，不让冲突的新旧规则同时有效。
- 相似信息可以合并，但不能丢掉适用条件或改变原意。
- 无法确定两条信息是互相替代还是适用于不同情况时，向用户说明并询问。
- “忘记”默认停止作为长期记忆使用，保留原对话和版本历史。操作结果明确展示这一范围，不将其称为彻底清除。

停止使用的记忆不再自动提供给 Agent，也不能仅因为原对话仍存在就自动重新保存。用户明确要求回顾原对话时，可以返回原记录，但应区分历史内容与当前有效偏好。

### 3.4 保持记忆精简

长期记忆有容量上限，用户可以查看已用容量。整篇资料和完整对话不塞进长期记忆。

达到容量限制时，说明无法保存的原因，展示可整理的内容；不能静默截断、丢弃现有条目，或在保存失败后声称已经记住。整理不得擅自删除仍有效且含义不同的信息。

当前采用与 Hermes 相同的默认容量：`USER.md` 1375 个 Unicode 字符，`MEMORY.md` 2200 个字符。

## 4. 历史对话与任务回忆

### 4.1 查找过去的内容

用户可以通过关键词或自然语言查找历史，并用时间、任务或对话缩小范围。例如：“上个月讨论研究计划时，你给了哪些修改意见？”

可检索的内容包括用户与 Agent 的消息，以及已保存的任务操作和结果。找到片段后，Agent 能继续读取前后文，避免只凭一句话解释整段讨论。

### 4.2 回答有历史依据

- 回答指向对应对话、消息或任务记录，用户可以打开查看上下文。
- 区分提议、用户决定、执行尝试和实际执行结果。
- 没有执行记录时，不把“准备发送”说成“已经发送”。
- 找不到匹配记录时，说明未找到，不用长期记忆推测当时具体说过什么。
- 检索历史不自动把所有命中内容重新保存为长期记忆。

刷新页面、重启服务或新建会话后，已保存的历史仍可检索。

## 5. 查看和管理记忆

### 5.1 三个使用入口

| 入口 | 呈现内容 | 用户操作 |
| --- | --- | --- |
| 当前对话 | 消息、可展示的工具结果和任务进度 | 连续提问、补充条件、继续当前任务 |
| 长期记忆 | “关于你”和“事实与约定”两个分区 | 查看、编辑、停止使用、查看历史版本和恢复 |
| 历史对话 | 历史会话列表、搜索结果与原消息 | 查找过去的讨论，打开命中位置和前后文 |

短期记忆体现在当前对话能接续交流，不提供单独的短期记忆编辑页面。上下文压缩不会删除页面上已保存的消息。

### 5.2 长期记忆页面与文件

长期记忆使用两个可直接阅读和编辑的 Markdown 文件；页面展示对应内容，文件修改与页面编辑作用于同一份记忆。

| 页面分区 | 对应文件 | 内容 |
| --- | --- | --- |
| 关于你 | `USER.md` | 用户背景、长期目标、语言、表达偏好和工作习惯 |
| 事实与约定 | `MEMORY.md` | 项目信息、环境事实、术语解释、稳定约定和经验 |

页面以简洁文字展示，例如：

> **关于你**
>
> - 默认使用简体中文。
> - 回答先给结论，再解释原因。
>
> **事实与约定**
>
> - Pebble 是对话优先的个人助手。

两个文件保存当前有效的长期记忆；完整历史对话、短期上下文与记忆变更历史不塞入这两个文件。来源与版本信息应可查看，但不要求用户维护技术字段。

用户能够：

- 查看当前有效记忆、适用范围、更新时间，以及可取得的来源对话。
- 区分用户直接录入的内容与 Agent 整理的内容；没有来源记录时不编造出处。
- 新增、编辑或停止使用记忆，查看修改前后的差异。
- 查看记忆变更历史，恢复误改或误删的记忆；恢复后从下一轮起生效。
- 从历史检索回答打开实际使用的消息和任务记录。

用户直接修改 `USER.md` 或 `MEMORY.md` 后，下一轮使用修改后的有效内容；不能只在界面中可编辑、实际文件变化却不生效。

记忆与变更历史应持久保存。版本界面使用“历史版本、查看差异、恢复”等用语，不要求使用者理解 Git。电脑和手机浏览器均能完成查看、修改和恢复操作。

停止使用与恢复均留下操作记录；停止使用后的内容不再作为有效记忆注入。历史检索仍可按用户要求找回原讨论，并标明原偏好已经停止使用。

### 5.3 对话中的记忆变更提示

变更成功后展示具体内容，并提供“查看记忆”入口：

- 新增：“已记住：回答先给结论，再解释原因。”
- 修改：展示“原内容 → 新内容”，让用户知道替换了什么。
- 忘记：“已停止使用这条记忆，原对话和版本历史仍保留。”

提示依据实际保存结果生成。未成功的操作不能显示为已完成；点击入口可以查看对应记忆或变更记录。

### 5.4 历史搜索与引用

用户可以浏览历史会话列表、搜索历史，也可以直接在当前对话中询问过去的事情。

搜索结果显示对话标题、时间和命中片段；基于历史的回答附对应消息或任务记录的引用。例如：

> 上次的考虑是将用户信息与项目事实分开，便于查看和维护。
>
> 来源：9 月 15 日 · Memory 设计讨论 · 查看原对话

引用必须对应实际查到的记录。点击后定位到相关消息或任务记录，并能继续查看前后文，而不只是打开会话首页。

## 6. 完整使用示例

### 6.1 记住、修正和忘记

1. 用户说：“以后先给我结论，再解释原因。”
2. Agent 保存偏好，并展示“已记住：回答先给结论，再解释原因”。
3. 用户新建会话提问，Agent 应用这一偏好。
4. 用户说：“以后改成先解释推导。”Agent 更新原偏好，展示旧内容与新内容。
5. 下一轮使用新偏好，不同时遵循旧偏好。
6. 用户说：“忘记这个回答顺序偏好。”Agent 停止使用，并说明原对话和版本历史仍保留。
7. 新会话不再自动应用该偏好，也不因检索到原对话就重新保存它。

### 6.2 回忆过去并继续任务

用户说：“我们上次为什么放弃 A 方案？按最后的决定继续。”

Agent 查找相关历史，读取必要上下文，解释有记录支持的原因，指向原消息，并区分讨论过的方案与最终决定。找到明确决定后继续处理；有多个候选或没有最终决定时，说明缺失信息并询问。

以上为验收示例，不要求每个任务固定经过同样的工具调用步骤。

## 7. 验收标准

以下均为应验证的产品行为，不代表已经实现或通过测试。

| 编号 | 用户操作或情境 | 可观察的结果 |
| --- | --- | --- |
| S1 | 先要求修改一段介绍，再说“再短一点” | 接续修改同一内容，保留本次已明确的条件 |
| S2 | 长对话触发上下文整理后继续任务 | 保留目标、决定、结果和未完成事项；页面原消息仍完整，精确细节可回查 |
| S3 | 刷新后继续原对话，再新建会话 | 原对话可继续；新会话不自动沿用上个任务的一次性要求 |
| M1 | 要求记住“先给结论”，再新建会话提问 | 无需重复说明，新会话按偏好回答；可查看已保存条目 |
| M2 | Agent 在普通对话中识别明确、长期有效的偏好 | 自动保存，并展示实际保存内容；不要求逐条确认 |
| M3 | 将同一偏好改成“先解释推导” | 下一轮采用新偏好；旧内容不再同时有效；可查看差异 |
| M4 | 平时用中文，本次要求英文 | 本次用英文；长期语言偏好不被改写 |
| M5 | 再次保存同一偏好 | 不产生重复条目 |
| M6 | 停止使用某条记忆，再新建会话 | 不自动应用，也不从原对话自动恢复该记忆；历史仍可查看 |
| M7 | 保存超过容量上限的内容 | 明确失败或展示整理需求；已有内容不丢失 |
| M8 | 保存工具失败 | 不声称记忆已生效 |
| M9 | 用户直接编辑记忆文件，或通过界面恢复旧版 | 下一轮读取正确的当前内容 |
| H1 | 查找过去讨论中的决定 | 找到真实记录，可打开前后文，结论与记录一致 |
| H2 | 历史中只有操作提议，没有成功结果 | 不报告操作已完成 |
| H3 | 重启服务后查找过去的讨论 | 已保存的历史仍可检索 |
| H4 | 没有匹配记录 | 明确说明未找到，不编造历史 |
| U1 | 在手机与电脑查看来源、修改和恢复记忆 | 两端均可完成，无需操作命令行 |
| U2 | 打开长期记忆页面并编辑两个分区 | “关于你”对应 `USER.md`，“事实与约定”对应 `MEMORY.md`；页面与文件内容一致 |
| U3 | 新增、修改、忘记一条记忆 | 对话显示实际内容或差异，可打开对应记忆或变更记录 |
| U4 | 搜索历史并点击结果或回答引用 | 显示标题、时间与片段，准确定位原记录，可查看前后文 |
| E1 | 完成第 6.1 节全部步骤 | 保存、跨会话应用、更新和停止使用形成完整链路 |
| E2 | 完成第 6.2 节任务 | 历史依据真实，最终决定与讨论内容区分准确 |

验收必须覆盖真实模型对记忆的应用、短期上下文保持与压缩后的任务接续、持久保存后跨会话读取、历史检索与界面定位。仅测试文件读写或使用固定模拟回答，不足以证明上述完整能力。

## 8. 尚需明确的范围：是否另做个人资料库

本次提出的“资料”指用户提供的独立文件，例如笔记、PDF、申请材料；它与记忆文件、历史对话不是同一个概念。

Hermes 的内置 Memory 核心是长期记忆文件及历史会话检索。本文不据此推导出一个必须实现的个人资料库。

之前讨论中的“导入文件、随文件变化更新索引、根据文件回答并定位原文”，属于独立的个人资料库需求。用户尚未决定是否将其与本次 Memory 一起交付，因此本文不纳入文件格式选择、资料索引、OCR 或资料编辑要求。

待决定的问题仅为：本次先完成本文的长期记忆与历史回忆，还是同时定义个人资料库？若同时定义，应单独写清其资料来源、支持格式、更新与引用行为。

## 9. Hermes 参考与差异

参考 Hermes 的三个核心思路：精简的长期记忆、可新增/替换/删除的维护工具，以及与长期记忆分开的历史会话检索。

本文有意采用的产品行为：

- 保存后的记忆从下一轮起生效；Hermes 文档描述的是会话开始时加载固定快照。这是本文提出的使用体验，整体确认时应一并确认。
- 主动记忆自动保存，并展示内容；“忘记”停止使用但保留历史。这两项已由用户明确选择。
- 长期记忆采用 `USER.md` 与 `MEMORY.md` 两个文件，页面分别呈现为“关于你”和“事实与约定”；默认容量采用 1375/2200 个 Unicode 字符，其他内部存储结构不要求照搬 Hermes。

本规格不包含可执行流程 Skill 的创建与审核，也不要求知识图谱、第三方记忆服务或后台自主复盘。邮件发送、日程创建等功能不由本文重新定义。
