# 技能（Skills）规格

技能域把可复用的工作方法沉淀为结构化文本，供模型在后续对话中按需加载。技能是"教助手怎么做事"的唯一载体：持久化可复用的方法，而不是存对话记录。全局规则见 `spec.md` §4。

## 1. 定位与范围

- 一个技能 = 一个目录（`skills/<skill_id>/`）：`SKILL.md`（元数据 + 正文）+ 可选附件（只允许 `references/`、`templates/` 两个子目录）。
- 技能有三种来源（origin）：`user`（用户手写）、`explicit`（用户明确要求助手创建）、`review`（后台复盘提炼）。
- 技能与资料库共享实例数据目录内的同一个本地 Git 仓库；每次变更一次提交，带结构化轨迹（变更 id、操作者、理由）。
- 模型不自动学习所有技能：会话中提供目录与用户选择的技能，未选正文按需加载；未变的材料不重复插入，变化时追加更新，新会话与压缩后重建。

## 2. 概念与数据

### 2.1 形态

| 字段 | 含义 |
| --- | --- |
| `name` / `description` | 必填。描述决定模型是否在正确场景加载该技能。 |
| `origin` | `user` / `explicit` / `review`（见 §1）。 |
| `managed` | 是否接受自动变更。用户手写技能默认 `false`；`explicit` / `review` 默认 `true`；可通过管理界面切换。 |
| `state` | `active` / `stale` / `archived`。只有 `active` 技能可被装配。 |
| `created_at` / `updated_at` | 时间戳。 |

`skill_id` 格式：小写字母数字开头，可含 `-`、`_`，≤64 字符。

### 2.2 版本（revision）

- `revision` = 技能全部内容的规范化哈希（名称、描述、正文、全部附件），**内容指纹而非 Git 提交号**——内容不变则版本不变。
- 版本历史与变更理由由 Git 提交消息承载（含变更 id、操作者、理由的结构化标注），可回溯、可恢复到任意历史版本。

### 2.3 变更（change）

一切写入走同一条变更管道，一条变更记录：动作（新建 / 打补丁 / 写文件 / 删文件）、操作者（`user` / `foreground` / `review`）、基于版本、状态（`proposed` / `applied` / `rejected` / `conflict`）、**证据**（指向本任务时间线中真实存在的条目）。

## 3. 装配（加载）

模型每轮看到技能的途径共三种，总量受预算约束（`spec.md` §6）：

1. **用户手动选择**：编写消息时通过技能菜单（`/` 或 ＋）选择，最多 **10 个**技能、正文合计 **40000 字符**，以内嵌材料"用户选择的技能"全文注入。提交时校验一次，装配时再次强制执行；用户的选择优先于技能内容自身的要求。
2. **技能目录**：常驻材料，最多 **50 条**（名称 + 描述），按最近使用排序，超出的注明省略；目录提示模型"相关时用 `skill_view` 读正文"。
3. **按需读取**：`skill_view` 加载正文或单个附件。

同一会话逐轮校验当前选择、状态与正文。相同材料沿用；新增或改变时追加完整内容，取消、排除、停用或无法装配时明确停止此前材料的适用。正文去重按技能身份区分，不把同名技能混为一个。目录顺序与数量规则保持不变。

规则：

- 用户可显式排除技能（进菜单剔除并关掉自动匹配）：被排除的技能在目录中不可见，`skill_list` / `skill_view` 也读不到——排除是硬约束，不依赖模型自觉。
- **工作区不干净（有未提交的磁盘改动）的技能不可装配**，直到重新保存收编：用户直改文件后技能自动从目录消失，防止未收编内容进入上下文。

## 4. 变更管道

- 单一写入入口，所有操作者共用；基于版本乐观校验，并发写产生 `conflict`，不覆盖。
- **用户手写技能（`origin=user` 且 `managed=false`）的自动变更只进入待审批状态**，由用户在管理界面批准或拒绝；`managed=true` 的技能与新建技能的自动变更直接应用。
- **任何用户侧写入（界面编辑、手写直改）将复盘游标重置并使代数（generation）+1**：在途的后台复盘候选全部失效为冲突，先用户的改动、后复盘的结果，不反向。
- 证据校验：变更声明的证据必须指向真实的时间线条目，伪造证据的变更被拒绝。

## 5. 后台复盘（review）

- **全局**（跨任务）触发：每完成 10 个用户消息轮（可配置）自动一次；也支持手动触发。同一时刻最多一个在途复盘；失败的复盘按退避重试，重启后恢复或标记中断。
- 复盘材料 = 技能目录 + 窗口内实际加载过的技能 + 窗口内的执行轨迹（对话、提示、工具调用，总量截断至 100 000 字符），轨迹条目以短证据引用（`E1`、`E2`…）标注，映射到真实时间线条目。
- 复盘在一个一次性专用会话中进行，只有技能工具与只读工具，产出**候选变更**（新建技能 / 修改既有技能）。
- **理由（reason）是给用户看的自然语言**：不得包含证据编号、id、技术引用；证据只出现在结构化证据字段。违规且拒不纠正的候选使整个复盘会话作废。
- 候选按序应用（内容相同则确定性变更 id）；应用遵循 §4 的审批规则；用户中途改写技能则候选按代数防护失效为冲突。
- 复盘以一句话结果收尾（如"复盘完成，N 条候选未应用"），不逐条打扰。

## 6. 工具面

| 工具 | Effect | Policy | 语义 |
| --- | --- | --- | --- |
| `skill_list` | `READ_ONLY` | `ALL_TURNS` | 列技能（尊重排除与状态）。 |
| `skill_view` | `READ_ONLY` | `ALL_TURNS` | 读正文或附件，返回当前 `revision` 与文件清单。 |
| `skill_manage` | `LOCAL_WRITE` | `USER_TURN_ONLY` | 修改技能。仅当**用户本轮明确要求**时使用；description 内置学习策略：沉淀可复用方法，不存对话记录。 |

后台复盘使用独立专用工具集：`skill_list`、`skill_view` 为只读，`skill_propose_change` 收集本地候选变更，三者均采用 `DEDICATED_SESSION_ONLY`，仅在技能复盘会话开放。

## 7. 存储与持久化

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 技能目录与附件 | `skills/<skill_id>/` | 与 `kb/` 共享实例数据目录的本地 Git 仓库；跨进程文件锁保护。 |
| 变更记录、审批状态、复盘窗口与游标、加载记录 | SQLite | 复盘游标为单调递增的完成轮序号 + 代数。 |

## 8. Web 界面

- 技能管理页：目录（按状态过滤 active / stale / archived + 搜索）、创建与编辑（正文 + 附件文件树与逐文件编辑）、`managed` 开关、归档与恢复、版本列表 / 详情 / 恢复到历史版本、每个技能的运行与使用记录。
- **待审批收件盘**：复盘产生的 proposed 变更，逐条批准 / 拒绝，可展开差异（diff）与证据（对应时间线条目）查看。
- 编写消息时的技能菜单：`/` 触发或 ＋ 菜单；选中的技能以不可编辑的行内标签呈现在输入框；可剔除技能并关闭自动匹配。

## 9. 失败与降级

| 情形 | 行为 |
| --- | --- |
| 手动选择超限 / 技能不可装配 / 正文超预算 | 记为降级步骤（`manual_skill_not_assembled`），消息照常发送，如实告知用户。 |
| 技能目录装配失败 | 记为降级步骤（`catalog_failed`），当轮无目录材料。 |
| 复盘失败 | 记录状态，按退避重试，不打扰用户。 |
| 磁盘直改未收编 | 技能不可装配（从目录消失），管理界面呈现待收编状态。 |

## 10. 验收标准

1. 每轮装配的技能符合预算：手动 ≤10 个且正文合计 ≤40000 字符，目录 ≤50 条；超限走降级并告知，不静默丢弃用户点名技能的选择。
2. 被排除的技能对模型完全不可见（目录、`skill_list`、`skill_view` 均不可达）。
3. `origin=user` 且 `managed=false` 的技能，任何自动变更只能以待审批状态存在，用户批准前不生效。
4. 用户写入后，在途复盘候选全部失效为冲突；不存在复盘覆盖用户手写内容的情况。
5. 复盘产出的理由是自然语言，不含证据编号或 id；证据字段全部指向真实时间线条目。
6. 工作区不干净的技能不出现在目录中，也不能被 `skill_view` 加载。
7. 每个技能的全部历史变更可追溯（操作者、理由、证据），可恢复到任意历史版本。
