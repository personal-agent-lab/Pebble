# 实现状态与已知偏差

本文件是唯一的状态记录：规格文档（`spec.md` 与各域文档）只写"应该是什么"，实现状态与已知偏差只写在这里。实现发生变化时更新本文件。

_更新于 2026-09-28，随文档重写建立的基线。_

## 总体

- 六个域（邮件、日历、记忆、资料库、技能、可观测性）与总纲描述的行为均已实现，有后端 pytest 与前端 Vitest 覆盖；三个外部边界（SDK 子进程、Gmail 投递、iCloud CalDAV）在自动化测试中使用替身。
- 部署形态：本机回环监听 + Tailscale Serve 远程访问（不使用 Funnel）；前端由后端同源托管。

- 后端：`uv run --project server pytest -c server/pyproject.toml`（仓库根执行）。

- 前端：`web/` 内 `npm run typecheck && npm test && npm run build`。


## 2026-10-04：固定用户设定的多轮虚拟世界评测

新增独立 `scenario_eval/`：场景以 world.json、user.md、expected.md、seeds/ 描述；模拟用户一次加载固定设定，只追加实际用户可见对话、卡片和操作结果，自主选择下一步。无阶段导演和逐轮换设定。运行器通过产品 HTTP 操作，沿用真实 Qoder SDK、MCP、Confirmation、SQLite、资料 Git 与历史检索。虚拟邮箱/日历是有状态客户端，发送、虚拟投递与核实都保存实际内容；来信在生产轮询建立游标后投递。所有场景结论仅由一次独立模型判断，程序只驱动、取证、校验格式及执行能力边界。

首场景“回复同事催材料，并在第二天核实是否发出”已完整运行。Agent 使用 Qwen3.8-Max；模拟用户及评审使用账号自定义 DeepSeek-Flash，模型显示名可从实时目录解析，同名托管型号优先，也可显式指定调用 ID。10 次用户模型调用保持同一设定版本；实际覆盖澄清、改期、隐藏细节、卡片编辑、最新版本确认、发送回报、受控跨日及新任务历史核实。邮箱与日历均为虚拟服务，未使用真实外部账号。受控服务时间同步至数据库/虚拟世界，并在评测查询中提供当前时间，不修改主机或 SDK 内置时钟，不声称真实等待24小时。

最终单次模型评审：结果 pass、过程 fail、纠正后完成、红线为空。实际邮件最终承诺周四下午五点前，用户确认后只发一封，正文与确认版一致。保留两处错误：首次未询问便写入交付承诺；次日先根据归档误报周四下班前，用户要求读取实际邮件后纠正。前期试跑还发现模拟用户非定向发言取消草稿、评审将待确认误当成承诺合理等问题；修正用户动作协议与通用信息边界提示后使用新实例重跑，旧原始报告保留，未重复评审同一运行。

最终证据与报告：`.eval-results/multiround-colleague-20261004-07/`。运行器为新场景复制材料快照，保存每次模型输入/提示/原始响应、事件、独立世界状态和一次评审结果；尚无全辅助调用的完整费用汇总。

验证：新增基础设施测试8项通过；Ruff（server、tests、scenario_eval）通过。全量 pytest 被工作区原先删除旧 evaluation 包留下的7处导入错误阻断，未恢复这些删除；排除 tests/evaluation 后最终488项通过。
