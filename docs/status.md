## 总体

- 六个域（邮件、日历、记忆、资料库、技能、可观测性）与总纲描述的行为均已实现，有后端 pytest 与前端 Vitest 覆盖；三个外部边界（SDK 子进程、Gmail 投递、iCloud CalDAV）在自动化测试中使用替身。

## 2026-10-08：结构化错误处理

新增统一 `Failure` 描述，保留错误码、简短原因、来源、阶段、影响、恢复建议、诊断编号与安全元数据。HTTP 已知业务错误保留原有字段与状态码，未知接口异常返回安全 JSON；MCP 工具错误沿用同一分类，继续交回模型。前台轮次、时间线与 SSE 保存及传递同一份原因，观测读取同步返回；schema 26 为轮次、时间线和后台回顾/复盘添加可空故障字段，旧记录保持原样，不根据旧文字追溯分类。

SDK 主轮及辅助会话区分明确的认证、计费、限流、请求拒绝、服务异常、协议、连接与进程错误。拒绝与内容过滤分开；当前 SDK 未保留上游 `isContentFilteredMessage`，内容过滤适配仅匹配 SDK 合成错误消息中的已知服务提示。页面默认显示一句“模型服务因内容过滤停止了回答”，详情默认折叠；已流出的部分回答保留，合成错误消息不混入正文。上游错误后的 SDK 退出异常不覆盖主因，失败不提交材料检查点。

Confirmation 外部执行异常和无效结果继续保守记为 `unknown`，异常值不进入执行回报；核实异常独立持久化，不覆盖原执行结论，详情可在邮件卡片查看。后台回顾/复盘记录结构化原因，标题失败保留原目标；成功轮之后的后台任务登记异常只记降级。观测与工具轨迹写入失败使用安全诊断日志；主错误落盘失败另记关联故障并释放运行槽位。未增加自动重试、自动清空会话、自动切换模型或外部再次执行；整体健康检查的模块覆盖仍沿用原实现，未扩展为全模块监控。
