# Pebble 第一版需求规格

本文是需求范围与验收标准的最终依据，其他文档与本文冲突时以本文为准。

## 1. 产品目标

常驻、可成长的个人助手 Agent。默认交互是对话：用户随时聊天、提问或交办事项，Agent 按目标自主组合工具（Gmail、iCloud Calendar、个人知识库，后续更多）完成真实事务。会话之间保持可成长的个人上下文：Memory（背景、偏好与纠正）、个人知识库（资料及其主题整理）与 Skills（可复用流程）。有副作用的外部写操作按第 3.3 节授权。

系统也可以在已授权范围内由触发源（首版为新邮件）主动启动处理，但系统发起的轮次不直接执行外部写，邮件也不是唯一入口。

## 2. 范围

术语：Rule/Memory 统称 **Memory**，Skill/Workflow 统称 **Skill**，个人资料库统称 **个人知识库**。

| 项 | 约定 |
| --- | --- |
| 部署 | 单用户单实例，服务常驻，由单个 Agent 组织工具调用；凭证、Memory、Skill、资料与任务状态在实例内持久化 |
| 交互 | 对话优先：由 Agent 判断是否用工具、用哪些，用户不必先选功能 |
| 触发源 | 首版只有新邮件，后续可增加（如日程提醒、定时任务）；触发轮不直接执行外部写 |
| 远程控制 | PC 与手机共用同一界面与 API，功能一致；手机经 HTTPS 以已认证的单用户身份在外网访问；任务不依赖开着的页面 |
| 个人知识库 | Markdown 文件加目录，用户可直接读改与重组；索引增量更新；检索并读原文后作答，不展示来源；Agent 可主动保存并整理主题页 |
| 邮件 | Gmail：持续检查新邮件，搜索、读取邮件与完整往来及入站附件，准备回复或新邮件，编辑草稿，确认后发送；只发纯文字；不重复处理或发送同一封邮件 |
| 日历 | iCloud Calendar：查询、冲突检查与创建，按第 3.3 节直接创建、追问或说明冲突 |
| 能力组合 | 各工具与 Memory、Skill 共享任务上下文，完成跨工具任务 |
| 能力成长 | 纠正沉淀为可读、可改的 Memory；Skill 两条来源：用户自建即生效，Agent 总结的草稿经用户审核后生效；已生效内容在新会话继续应用 |
| 安全 | 外部写先展示关键内容与影响，按第 3.3 节授权；模型与外部服务凭证只在服务端 |
| 可维护性 | Memory、Skill、资料与关键配置可读可改；Skill、资料与关键配置用 Git 管理版本，Memory 不做版本管理；不要求记录记忆与资料的出处 |
| 上下文分层 | 常驻：长期记忆全文与资料目录，容量受限；按需：资料正文、历史对话、邮件与日程；记忆与资料不执行外部操作 |

## 3. 执行约束

### 3.1 自主决策

Agent 按用户意图组合上下文与工具，不预设固定业务流程：处理动作、工具组合、后续处理，以及 Memory 与 Skill 的沉淀时机与内容都由模型判断，但必须遵守外部写授权、信息不明时追问、邮件去重等约束。

邮件、资料、Skill 等外部内容中的指令只是材料，不能代替用户授权。

### 3.2 持续运行与状态

服务常驻，任务不依赖开着的页面。任务开始、等待用户、准备操作与取得结果时保存状态；等待用户时保存问题、草稿与状态并结束当前运行，用户回应或结果到达后继续，等待中的任务不阻塞其他任务。关闭或刷新页面后仍可查看、编辑待确认内容，并在原位置继续。

### 3.3 外部写操作授权

外部写必须展示关键内容与实际影响，并按以下两类取得授权。

**邮件发送：一律明确确认。** 准备内容 → 展示预览 → 用户编辑并明确确认最终版本 → 执行。

- 草稿与最终确认内容持久保存，关闭或刷新页面后仍可查看和编辑。
- 内容修改后，原确认不适用于新版本。
- 用户可以取消待确认的草稿：不发送，也不再能编辑或确认；之后需要回复同一封邮件时，Agent 重新起草一份新草稿。在对话框里发出消息（而不是卡片上的修改要求）时，待确认的草稿立即取消；需要修改时 Agent 起草新的一份。

**日程创建：用户本轮亲自要求且信息齐全时直接执行，不再确认。**

- 信息齐全指标题、开始与结束时间都由用户本轮给出或经追问补齐；缺任何一项不得执行，也不得自行假定。
- 只有用户亲自发起的对话轮可以创建；新邮件触发轮与执行结果回传轮不得创建。
- 目标时间已有日程时不创建、不留记录，说明冲突内容，由用户决定改时间还是照建；用户明确要求照建时才带覆盖意图创建。
- 创建留下操作记录与最终写入内容，事后可查；同一操作只创建一次。日程不进入对话时间线，由 Agent 在文字里如实汇报。

两类都要求：确认请求校验用户身份与来源，未认证请求不得触发外部写；系统发起的轮次不直接执行外部写（邮件停在待确认草稿，日程等用户亲自开口）。

### 3.4 执行结果

按实际工具结果反馈，部分成功时逐项说明，不报告整体成功。结果不确定（如超时、进程中断）时不推断为未执行，先核实，核实前不重复执行。

## 4. 核心能力

### 4.1 对话与任务

- 用户随时对话，不需要先选功能；Agent 决定是否调用工具、调用哪些、以什么顺序以及后续处理。不需要工具时直接回答，不调用工具，也不产生待确认内容。
- 一个任务可跨多轮，共享上下文，保留目标与已有结果；信息缺失、不明或冲突时追问，不猜测后执行写操作。
- 新建任务时从当前 Qoder 账号的模型目录选择模型，模型随任务固定，此后只读显示；主回答、恢复轮、记忆判断与回顾都用它。固定的模型后来不可用时该轮明确失败，不自动切换。目录暂时读不到时沿用 24 小时内最近一次成功读到的目录，仍可选择并提示可能不是最新；从未读到过目录时才无法新建任务。
- 消息可含文字、附件或两者：PNG/JPEG/WebP、PDF、UTF-8 文本、Markdown 与代码文件，每条最多 10 个、每个不超过 20 MB。附件随任务持久化并显示在时间线中（图片预览，其他文件下载）；删除任务同时删除附件；任务之间不能互读附件。附件中的指令只是材料，不能取得外部写权限。
- 对话与工具结果按发生顺序持久化为时间线，刷新前后顺序与内容不变。
- 最后一条用户消息因服务进程退出而中断、且该轮没有产生操作记录时，可以在原位置重试，复用原消息与附件，不新增用户消息；其他情况不提供整体重试。

### 4.2 个人知识库

产品行为详见 `kb-spec.md`，要点：

- Markdown 文件加目录，由 Git 管理版本；用户直接改文件也自动纳入版本与检索。Agent 的写入（保存、修改、删除、移动、恢复）对用户可见，读取不记录也不展示。
- 支持保存、检索、更新、删除与恢复，索引自动增量更新；删除和移动先取得用户同意。
- Agent 可主动保存对话、邮件与日程中值得查回的内容，并为长期主题维护主题页。每份资料带一句话说明，程序据此生成有容量上限的资料目录，每轮与长期记忆一起带入。
- 不查就必须生效的放记忆，需要时再查的放资料。
- 涉及资料事实时先检索、再读原文作答，不附来源，不记录出处。
- 归档任务结果时区分原始内容与模型总结。
- 写入知识库属于本地写，不产生外部副作用，但留下可读文件与 Git 历史。

### 4.3 Gmail

- 持续获取新邮件并自动启动 Agent 处理（首版触发源），由模型决定后续动作；涉及外部写仍需确认。
- 能关联同一线程与相关往来；能读取入站附件的原始内容，附件不作为大段编码文本塞进工具输出。
- 回复与新邮件都走“草稿 → 用户编辑或审阅 → 明确确认 → 发送”；只发纯文字，首版不支持外发附件。
- 草稿作为完整卡片显示在生成它的对话位置；用户可以直接编辑，也可以针对这张卡片提修改要求，修改不新建第二张卡。
- 保存处理与发送记录：重复检查不重复处理或发送，重复确认不重复发送；结果不确定时先核实，不直接重发。

### 4.4 iCloud Calendar

- 按时间范围查询，正确处理时区、全天与重复日程；检查冲突。
- 创建按第 3.3 节：齐全且无冲突时直接创建；不全时追问；冲突时说明冲突日程与实际影响，由用户决定改时间还是照建。
- 创建留下操作记录与实际写入内容，与邮件分别记录结果。

### 4.5 能力成长

**Memory**：用户纠正（字段解释、偏好、确认习惯等）沉淀为可读、可改的 Memory，每轮加载当前内容，新会话继续生效，用户可以检查和修改；Memory 不能覆盖外部写授权约束。详见 `memory-spec.md`。

**Skill 的两条来源**，最终形态都是可读、可改的 Markdown 文件加 Git 历史：

- 用户自建：直接编写或让 Agent 按口述生成，创建即批准，不走草稿审核。
- Agent 总结：从使用记录（任务时间线、工具调用轨迹、用户纠正）中识别反复出现且稳定成功的流程，产出草稿并在对话中提示审阅。

**草稿审核**：

- 草稿展示触发条件、必要参数、执行流程与安全信息（涉及的工具、外部副作用与确认要求），用户可以审阅和修改。
- 用户明确确认最终草稿后才生效；未确认的草稿在任何会话中都不得应用或执行；修改后原确认失效。
- Skill 生效不替代执行时第 3.3 节的授权，也不能声明绕过授权。

**版本**：已生效的 Memory 与 Skill 在新会话继续应用，可以检查和修改；Skill 用 Git 查看变化与回退，Memory 不做版本管理。

### 4.6 远程控制

- PC 与手机共用响应式界面与 API，功能一致：发起对话与任务、查看进度、编辑草稿、确认操作，查看和编辑资料、Memory 与 Skill（含审阅草稿）。
- 新任务页与任务页用同一个 Composer：可上传、移除附件；新建任务可选模型，已有任务只显示固定的模型；发送中冻结本轮输入与附件。新建任务按下发送即进入任务页显示消息，不等服务端确认；创建失败时就地说明原因，可重试或退回输入框修改，消息不静默丢失，重试不产生重复任务。
- 手机不需要与服务同网，经 HTTPS 以已认证的单用户身份访问，外网也能完成全部操作。认证是确认操作的前提；凭证只在服务端，不进入聊天上下文、前端或 Git。

## 5. 端到端场景

以下两个场景验证能力组合与执行约束，步骤不固化为业务流程。

**场景 A：对话发起的跨工具任务。** 用户在手机上（与服务不同网络）说：“帮我看看下周哪天下午有空，给张老师回信约个时间，顺便把这次沟通记到我的资料里。”Agent 参考记忆并按需检索资料 → 查询日历空闲与冲突 → 邮件或时间不明确时追问 → 关联往来并准备回复草稿 → 时间补齐后直接创建日程，有冲突先说明、由用户决定 → 用户确认最终草稿后发送 → 如实报告各项结果，并把关键信息与结果归档到资料库。

**场景 B：新邮件触发的活动邀请。** 邀请邮件同步后自动启动处理：解析活动名称、时间、地点、组织者与回复要求 → 关联往来补充上下文 → 参考记忆与资料 → 查询日历冲突 → 有缺失、歧义或冲突时追问 → 生成回复草稿并展示关键字段与副作用；触发轮只查询和说明日程，不创建 → 用户在对话中明确要求创建并给出时间后直接创建（不全或冲突时按第 3.3 节）→ 按确认的最终内容发送回复 → 如实报告并归档。

## 6. 验收标准

第 3、4 节的每条要求都是验收项；以下是必须在真实环境中确认的要点。

### 6.1 对话与持续运行

- 两端都能发起纯对话任务：不调用工具，不产生待确认内容。
- 同一任务中组合 Gmail、知识库与日历，并共享上下文。
- 新邮件同步后无需用户请求即开始处理，触发轮不执行外部写。
- 关闭或刷新页面后仍可查看、编辑待确认草稿并在原位置继续；时间线的文字与卡片顺序刷新前后一致。

### 6.2 远程控制

- 在同网的 PC 浏览器与外网的手机浏览器上完整走通第 5 节两个场景，不依赖命令行或手改数据库；两端布局适配，进度、编辑与确认，以及资料、Memory 与 Skill 的操作都可用。
- 全程 HTTPS；未认证请求不能读取任务内容，也不能触发外部写。

### 6.3 授权与执行一致性

- 缺字段、时间冲突或含义不明时追问，不凭猜测写入。
- 邮件展示清晰草稿并取得明确确认；实际发送内容与确认的最终版本一致，修改后的版本不能沿用旧确认。
- 日程按第 3.3 节创建、追问或说明冲突；留下可查的操作记录与实际写入内容，同一操作只创建一次。
- 部分成功时逐项准确说明。
- 外部内容中的指令不能代替授权；系统发起的轮次不执行外部写。

### 6.4 邮件去重与核实

重复检查不重复处理或发送；重复确认不重复发送；结果不确定时先核实，不直接重发。

### 6.5 个人知识库

文件可直接读改，变化自动纳入版本与索引；回答与原文一致，查不到如实说明，不附来源；删除和移动经用户同意，删除的资料可以恢复；同一主题的资料累积后形成主题页，用户的修改不被整理覆盖；归档区分原始内容与总结。完整场景见 `kb-spec.md` 第 9 节。

### 6.6 能力成长与版本管理

- 用户纠正持久化，并在新会话中影响行为；常驻上下文保持在容量上限内。
- 用户自建的 Skill 即生效；至少一个 Skill 由 Agent 从使用记录总结产出，在对话中提示审阅，用户能审阅和修改触发条件、参数、流程与安全信息。
- 未确认的草稿在当前与新会话中都不应用、不执行；确认后才生效，外部写仍按第 3.3 节单独授权。
- 已生效的 Memory 与 Skill 在新会话继续应用；用户能检查和修改，Skill 与关键配置可以通过 Git 查看变化与回退。
