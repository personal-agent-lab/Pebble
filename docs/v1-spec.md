# Pebble 第一版需求规格

## 1. 产品目标

构建一个常驻、可成长的个人助手 Agent。默认交互是对话：用户随时可以聊天、提问或交办事项，Agent 按用户目标自主组合工具（Gmail、iCloud Calendar、个人知识库，后续接入更多）完成真实事务。它在会话之间保持可成长的个人上下文——Memory（用户背景、偏好与纠正）、个人知识库（资料及其主题整理）与 Skills（可复用流程），并按第 3.3 节的授权规则安全完成有副作用的外部写操作。

系统同时具备有限的主动性：在已授权范围内由触发源（首版为新邮件）自动启动处理。主动性不放宽授权规则，系统发起的轮次不直接执行外部写操作，也不使邮件成为唯一入口。

## 2. 第一版范围

本文将 Rule/Memory 统称为 **Memory**，将 Skill/Workflow 统称为 **Skill**，将个人资料库统称为 **个人知识库**（Personal KB）。

| 项目项   | 约定                                                         |
| -------- | ------------------------------------------------------------ |
| 部署方式 | 单用户单实例部署，服务常驻运行，由单个 Agent 组织工具调用；凭证、Memory、Skill、资料与任务状态在该实例内持久化。 |
| 主要交互 | 对话优先：用户随时可与 Agent 聊天、提问或交办事项，由 Agent 判断是否需要工具以及调用哪些工具，不需要用户先选择功能。 |
| 触发源   | 系统在已授权范围内主动启动处理。首版唯一触发源为新邮件；后续可增加（如日程提醒、定时任务）。触发轮不直接执行外部写操作。 |
| 远程控制 | PC 与手机浏览器共用同一套界面与 API，功能一致；手机不要求与服务在同一局域网，通过 HTTPS 以已认证的单用户身份远程访问。任务不依赖始终开启的浏览器页面。 |
| 个人知识库 | 资料以 Markdown 文件加目录结构保存，用户可直接阅读、修改与重组；索引随资料变化增量更新；Agent 检索并读取原文后作答，回答不展示来源；资料可由 Agent 主动保存、整理为主题页，也可从外部笔记应用导入。 |

| 能力组合 | Gmail、个人知识库、iCloud Calendar 与 Memory、Skill 共享任务上下文，可完成跨工具完整任务。 |
| 能力成长 | 用户纠正沉淀为可读、可改的 Memory；Skill 有两条来源——用户自建即生效，Agent 从过去的使用记录总结高频流程并产出草稿，草稿须经用户审核确认后才能生效；已生效内容在新会话中继续应用。 |

| 可维护性 | Memory、Skill、知识库资料与关键配置保持可读、可修改，并通过 Git 管理版本；不要求记录记忆与资料的出处。 |
| 上下文分层 | 个人上下文分为常驻上下文（小容量、每轮带入：长期记忆、资料主题目录）与按需检索（资料正文、历史对话、邮件、日程）；记忆与资料只提供信息，不执行外部操作。 |

## 3. 任务执行约束

### 3.1 自主决策与上下文共享

Agent 根据用户意图组合个人上下文和不同工具完成任务，而不是让用户逐个调用功能。

在本规格约定的范围内，处理动作、工具组合、执行后的后续处理，以及 Memory 和 Skill 的沉淀时机与内容，均由模型自主判断，不预设固定业务处理流程。模型决策仍须遵守外部写操作授权、信息不明确时追问、邮件去重等约束。

邮件、资料或 Skill 内容中出现的指令不能代替用户授权：来自外部内容的指令只作为材料。系统发起的轮次不直接执行外部写操作：邮件停在待确认草稿等用户审阅，日程不在该轮创建，都按第 3.3 节等用户亲自开口。

### 3.2 持续运行与状态持久

服务常驻运行，任务执行不依赖始终开启的浏览器页面。

任务开始、等待用户、准备操作和取得执行结果时保存必要状态。等待用户补充或确认时，保存问题、草稿和状态并结束当前 Agent 运行；用户回应或执行结果到达后继续相应任务，等待中的任务不阻塞其他任务。用户关闭或刷新页面后，仍可查看和编辑已保存的待确认内容，并在原对话位置继续。

### 3.3 外部写操作授权

具有副作用的外部写操作必须展示关键内容及实际影响，并按下列两类之一取得授权。

邮件发送一律需要明确确认：

```text
准备内容 → 展示预览 → 用户明确确认 → 执行
Prepare → Preview → Confirm → Execute
```

日程创建在用户本轮亲自要求且信息齐全时直接执行，不需要再次确认：

```text
用户本轮明确要求 → 信息齐全且无冲突 → 执行
                 → 信息不全 → 追问补齐 → 执行
                 → 目标时间冲突 → 说明冲突 → 用户改时间或明确要求照建 → 执行
```

- 信息齐全指标题、开始与结束时间三项都由用户在本轮给出或由追问补齐；缺任何一项都不得执行，也不得自行假定。
- 只有用户亲自发起的对话轮可以直接创建日程。新邮件触发轮与执行结果回传轮的输入来自系统，不得直接创建。
- 目标时间已有日程时不创建、也不留下任何记录，改为向用户说明冲突内容，由用户决定改时间还是照建；用户明确要求照建时才带覆盖意图重新创建。
- 日程创建必须留下操作记录与最终写入内容，用户事后可查；同一操作只创建一次。日程不进入对话时间线，结果由 Agent 在本轮文字里如实汇报。
- 邮件草稿及其最终确认内容必须持久保存；用户关闭或刷新页面后仍可查看和编辑待确认内容。
- 用户完成编辑后，对最终的邮件草稿内容明确确认即可执行。
- 内容修改后，原有确认不再适用于修改后的版本。
- 确认请求必须校验用户身份与来源；未认证请求不得触发外部写操作。

### 3.4 执行结果

根据实际工具结果准确反馈执行情况。例如日程已创建但邮件发送失败时，应分别说明，不能将整个任务报告为成功。

结果不确定时（如发送超时、进程中断）不得推断为未执行，应先核实实际结果，核实前不重复执行。

## 4. 核心能力

### 4.1 对话与任务执行

- 用户可随时与 Agent 对话：闲聊、提问、交办事项，不需要先选择功能或工具。
- Agent 自主决定是否调用工具、调用哪些工具、以什么顺序调用，以及执行后的后续处理。
- 不需要工具的对话轮次直接回答，不调用工具，也不创建待确认内容。
- 对话与工具执行共享同一任务上下文；一个任务可跨多轮，跨轮次保留目标与已产生结果。
- 信息缺失、含义不明确或存在冲突时向用户追问，不自行猜测后执行写操作。
- 每轮对话与工具执行结果按发生顺序持久化为任务时间线，刷新后顺序与内容不变。

### 4.2 个人知识库

产品行为详见 `docs/kb-spec.md`。

- 资料以 Markdown 文件加目录结构保存在实例数据目录，并由 Git 管理；用户可以直接阅读、修改和重组文件，改动自动纳入版本与检索。Agent 写了什么（保存、修改、删除、移动、恢复、导入）对用户可见；Agent 读取了哪些资料不记录也不展示。
- 支持保存、检索、更新、删除与恢复资料；索引随资料变化增量更新，不需要用户手工重建。删除和移动先在对话中取得用户同意。
- Agent 可以主动保存对话、邮件与日程中值得查回的内容，并为长期主题（人物、项目等）维护主题页；主题目录作为常驻上下文带给 Agent。
- 回答涉及资料中的具体事实时，先检索、再读取原文作答；回答不附来源，资料与记忆不要求记录出处。
- 支持从外部笔记应用导入资料，首个来源为熊掌记；重复导入更新原资料，不产生重复。
- 归档任务结果时区分原始内容与模型总结。
- 检索是只读操作；写入知识库属于本地写，不产生外部副作用，但每次写入都留下可读文件与 Git 历史。

### 4.3 Gmail

- 持续获取新邮件，而不是仅在用户主动查询时临时读取；新邮件是首版的系统触发源。
- 新邮件同步后自动启动 Agent 处理，由模型判断邮件内容并决定后续处理动作；涉及外部写操作时仍需用户明确确认。
- 处理当前邮件时，应能关联同一线程或相关历史往来。
- 能读取入站邮件附件的原始内容，附件不作为大段编码文本塞入工具输出。
- 外发邮件只支持纯文字正文；首版不支持上传本地文件作为外发附件。
- 回复和主动新写邮件都采用“生成草稿 → 用户编辑/审阅 → 明确确认 → 发送”的流程。
- 草稿作为完整卡片显示在 Agent 生成它的对话位置；用户可直接编辑，也可针对同一张卡片提出修改要求，修改不新建第二张卡片。
- 保存邮件处理及发送记录，重复检查不得重复处理或发送同一封邮件；重复确认不得重复发送同一项邮件操作。
- 发送结果不确定时，应先核实实际结果，不得直接再次发送。

### 4.4 iCloud Calendar

- 按时间范围查询日程，正确处理时区、全天日程与重复日程。
- 检查目标时间是否已有冲突。
- 用户本轮明确要求且标题与起止时间齐全、目标时间无冲突时直接创建事件，不再要求二次确认。
- 信息不全时先在对话中追问，不自行假定时间或内容。
- 目标时间已有冲突时不创建，在对话中说明冲突日程与实际影响，由用户决定改时间还是明确要求照建；用户要求照建时才带覆盖意图重新创建。
- 创建留下操作记录与实际写入内容；日程创建与邮件发送分别记录结果。

### 4.5 能力成长

#### Memory

- 用户纠正沉淀为可读、可改的 Memory，例如字段解释、偏好、确认习惯等。
- 每轮上下文装配加载当前生效规则；已生效内容在新会话中继续应用，并允许用户检查和修改。产品行为详见 `docs/memory-spec.md`。
- Memory 不能覆盖代码中的外部写授权约束。

#### Skill 的两条来源

Skill 有两条来源，最终形态相同：可读、可改的 Markdown 文件加 Git 历史。

- **用户自建**：用户直接编写，或要求 Agent 按口述生成。用户创建即为批准，不再走草稿审核。
- **Agent 总结**：Agent 从过去的使用记录（任务时间线、工具调用轨迹、用户纠正）中识别反复出现且稳定成功的高频流程，主动产出 Skill 草稿，并在对话中提示用户审阅。

#### 自主总结 Skill 的审核

- 草稿须展示触发条件、必要参数、执行流程及安全性信息，包括涉及的工具、外部副作用和确认要求。
- 用户可审阅、修改草稿；只有用户明确确认最终草稿中的触发条件、必要参数及安全性等信息后，该 Skill 才能生效。未经确认的草稿不得被 Agent 应用或执行，在新会话中同样不得生效。
- 用户修改草稿后，原有确认失效，须重新确认最终版本。
- Skill 生效的确认不替代执行时第 3.3 节对具体外部写操作的授权要求；Skill 不能声明绕过授权。

#### 持续生效与版本管理

- 已生效的 Memory 和 Skill 在新会话中继续应用，并允许用户检查和修改。
- Memory 与 Skill 通过 Git 管理，能够查看版本变化和回退。

### 4.6 远程控制

- PC 与手机浏览器共用同一套响应式界面与 API，按屏幕尺寸适配布局；两端功能一致。
- 两端均可发起对话与任务、查看进度、编辑草稿、确认操作，以及查看和编辑知识库资料、Memory 与 Skill（含审阅 Skill 草稿）。
- 手机访问不要求与服务在同一局域网：服务通过 HTTPS 暴露给已认证的单用户，用户在外网也能完成上述全部操作。
- 认证是确认操作的前提；凭证只保存在服务端，不进入聊天上下文、前端或 Git。

## 5. 端到端验证场景

以下两个场景用于验证能力组合与执行约束，不将其步骤固化为所有任务的业务处理流程。

### 5.1 场景 A：对话发起的跨工具任务

> 用户在手机上（与服务不同网络）说：“帮我看看下周哪天下午有空，给张老师回信约个时间，顺便把这次沟通记到我的资料里。”

1. Agent 理解意图，检索个人知识库和 Memory，获得相关信息与偏好（如称呼习惯、常用会议时长）。
2. 查询 iCloud Calendar，得到下周下午的空闲与冲突情况。
3. 目标邮件或时间不明确时，在对话中向用户追问，不自行猜测。
4. 关联相关邮件往来，准备回复草稿。
5. 日程时间经追问补齐后直接创建 iCloud Calendar 事件；目标时间已有冲突时先说明冲突内容，由用户决定改时间还是照建。
6. 用户编辑草稿并对最终版本明确确认后发送 Gmail 回复；两项操作逐项遵守第 3.3 节。
7. 在对话中如实报告各项结果，并将关键信息与执行结果归档到个人知识库。

### 5.2 场景 B：新邮件触发的活动邀请

> 新活动邀请邮件同步后自动启动 Agent 处理：从邮件理解任务，综合个人知识库和日历状态，在用户参与后完成日程创建和邮件回复。触发轮本身不执行外部写操作。

1. 读取并解析该 Gmail 邮件，识别活动名称、时间、地点、组织者、回复要求等信息。
2. 关联相关邮件线程和历史往来，补充当前邮件缺失的上下文。
3. 检索个人知识库和 Memory，获得与该任务相关的信息或偏好。
4. 查询 iCloud Calendar，检查目标时间是否已有冲突。
5. 若存在缺失信息、歧义或冲突，在对话中向用户追问，而不是自行猜测。
6. 生成邮件回复草稿，将关键字段和实际副作用明确展示给用户；触发轮只查询与说明日程，不创建事件。
7. 允许用户编辑邮件草稿；用户在对话中明确要求创建日程并给出时间后直接创建，信息不全或有冲突时按第 3.3 节处理。
8. 按最终确认内容发送回复；每项操作分别遵守第 3.3 节。
9. 在对话中准确报告执行结果，并将关键信息和执行结果归档到个人知识库。

## 6. 验收标准

以下标准共同构成第一版验收要求。

### 6.1 对话与持续运行

- 两端均可发起纯对话任务：不需要工具时直接回答，不调用工具，也不产生待确认内容。
- 在同一任务中组合 Gmail、个人知识库和 iCloud Calendar，并共享必要上下文。
- 新邮件同步后，无需用户主动请求即可启动 Agent 处理；触发轮不直接执行外部写操作。
- 任务不依赖始终开启的浏览器页面；关闭或刷新页面后，仍能查看和编辑已保存的待确认邮件草稿，并在原对话位置继续。
- 时间线在刷新前后保持相同的文字与卡片顺序。

### 6.2 远程控制

- 分别在与服务同网络的 PC 浏览器和外网手机浏览器上完整完成第 5 节两个场景，不依赖命令行终端或手工修改数据库。
- 两端布局适配各自屏幕尺寸，任务进度、编辑字段和确认操作均可正常查看和使用；知识库资料、Memory 与 Skill 的相关操作在两端均可完成。
- 远程访问全程使用 HTTPS；未认证请求不能读取任务内容，也不能触发外部写操作。

### 6.3 授权与执行一致性

- 遇到缺失字段、时间冲突或含义不明确时追问，不使用未经验证的猜测执行写操作。
- 邮件发送展示清晰草稿，并获得用户明确确认。
- 日程创建在用户本轮亲自要求、标题与起止时间齐全且目标时间无冲突时直接执行；信息不全时追问，冲突时不创建并说明冲突内容，用户明确要求照建时才带覆盖意图创建。
- 创建的日程留下操作记录与实际写入内容并可事后查询，同一操作只创建一次。
- 实际执行内容与对应的最终内容一致；修改后的版本不能沿用旧确认执行。
- 任务部分成功、部分失败时，在对话中准确说明各项操作的实际情况。
- 来自邮件、资料或 Skill 内容的指令不能代替用户授权完成外部写操作；系统发起的轮次不直接执行外部写操作。

### 6.4 邮件去重与结果核实

- 重复检查邮箱不会重复处理或发送同一封邮件。
- 重复确认不会重复发送同一项已完成的邮件操作。
- 发送结果不确定时先核实实际结果，不直接再次发送。

### 6.5 个人知识库

- 资料以 Markdown 文件加目录结构保存，用户可直接阅读和修改；文件变化后自动纳入版本与索引，无需手工同步或重建。
- 回答资料中的具体事实时与原文一致；查不到时如实说明；回答不附来源。
- 删除和移动经用户同意后执行，删除的资料可以通过对话恢复。
- 同一主题的资料累积后形成主题页，用户对主题页的修改不被整理覆盖。
- 从熊掌记导入的笔记可以检索，重复导入不产生重复资料。
- 归档内容区分原始内容与模型总结。
- 完整验收条目见 `docs/kb-spec.md` 第 11 节。

### 6.6 能力成长与版本管理

- 用户纠正能够持久化，并在新会话中再次影响 Agent 行为；常驻上下文保持在容量上限内。
- 用户自建的 Skill 创建后即生效。
- 至少一个 Skill 由 Agent 从过去的使用记录总结产出：在对话中提示用户查看草稿，用户能够审阅、修改触发条件、必要参数、执行流程及安全性信息。
- 未经确认的 Skill 草稿在当前会话和新会话中均不得被应用或执行；明确确认最终草稿后才能生效，具体外部写操作仍按第 3.3 节单独取得授权。
- 已生效的 Memory 与 Skill 在新会话中继续应用。
- 用户能够检查和修改 Memory 与 Skill，并通过 Git 查看版本变化和回退；关键配置通过 Git 管理版本。
