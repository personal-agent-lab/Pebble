# 可观测性（Observability）规格

可观测性回答两个问题：**这一轮到底发生了什么**（工具调用、压缩、降级）与**上下文花了多少**（材料、消息、余量）。观测是纯被动的：不向模型暴露任何观测工具，不影响任何产品行为，只为用户与开发提供事后事实。

## 1. 定位与范围

- 观测对象是轮次（run）：每次进入 Agent 的轮产生一份轮次观测 + 若干步骤。
- 数据来自程序自身的记录点（装配、工具边界、会话回调），不依赖模型自觉汇报。
- 观测失败本身也按降级记录，永不阻断对话与工具执行。

## 2. 数据

| 数据 | 含义 |
| --- | --- |
| 轮次观测（run observation） | 每轮一份：注入材料清单（含渲染后字符数、被跳过的材料）、会话结果、轮前 / 轮后上下文读数、用量汇总。 |
| 步骤（step） | 轮内的原子记录，三类：**工具**（开始 / 结束 / 状态）、**压缩**（上下文压缩边界）、**降级**（见 §4）。状态：运行中 / 成功 / 失败 / 被拒绝。 |
| 时间线工具条目 | 工具调用的参数与结果文本，按（轮次、调用 id）唯一；**同时是技能复盘的证据基底**——复盘证据引用的就是这些条目。 |
| 上下文读数 | 轮前与轮后各一次：各部分占用与剩余百分比，与客户端 `/context` 视角一致。 |

规则：

- 压缩边界只在收到真实信号时记录，不推测。
- 步骤随轮次级联删除；时间线条目随任务保留。
- 用量按消息 / 请求去重汇总；无法得到可靠数值时记"未记录"，不编造。
- SDK 提供缓存读写 token 时保留请求级与会话累计读数；缺失不补零，不以材料去重或会话恢复推算缓存收益。

## 3. 记录点

| 记录点 | 产出 |
| --- | --- |
| 上下文装配 | 实际经钩子提交的材料清单、渲染字符数、跳过列表；复用的背景不计为本轮新增。 |
| 工具边界 | 每次调用的开始 / 结束步骤 + 时间线工具条目；未知与被拒绝的调用同样记录。 |
| 会话回调 | 文本增量、压缩边界、上下文读数、用量。 |
| 后台任务 | 记忆判断、目录装配、技能装配等失败 → 降级步骤。 |

## 4. 降级类别

降级 = 功能性失败但不阻断对话的既编码事件：

| 代码 | 含义 |
| --- | --- |
| `catalog_failed` | 资料 / 技能目录装配失败，当轮无目录材料。 |
| `manual_skill_not_assembled` | 用户选择的技能因超限 / 不可装配 / 正文超预算未能注入。 |
| `memory_judge_failed` | 轮内记忆判断失败（不重试）。 |
| `tool_trace_write_failed` | 工具轨迹写入失败（观测自身失败也如实记录）。 |

## 5. 健康检查

`/api/health` 是唯一的整体状态出口：

- `status`：`ok` / `degraded`（如邮件同步游标失效）。
- `services`：各可选服务（Gmail、iCloud Calendar）的配置状态（`configured` / `unconfigured`），见 `spec.md` §9。

## 6. 查看途径

- 接口：按任务读取轮次观测与步骤。
- Web：任务时间线的运行详情（逐工具定位、双向跳转）、上下文表（ContextMeter：system prompt / 系统工具 / 技能 / 消息 / 其他 / 剩余）、状态徽章。

## 7. 验收标准

1. 每轮恰好一份轮次观测，含轮前 / 轮后两次上下文读数。
2. 每次模型发起的工具调用（包括被拒绝与未知的）在步骤与时间线中各有一条记录。
3. §4 列出的降级情形发生时，对应步骤一定存在；未发生时不出现。
4. 观测写入失败不改变对话与工具的行为。
5. 时间线工具条目可作为复盘证据被引用；引用不存在的条目会被拒绝（见 `skills.md` §4）。
6. 用量与上下文百分比有真实来源，取不到时显示"未记录"而不是估算值。
