# 真实场景评测运行器

`docs/evaluation.md` 的实现载体：在真实模型、真实产品接口下驱动隔离实例，
验证产品行为（pytest 用替身锁程序逻辑，二者互补）。

## 前提

- **模型凭证**：`QODERCN_PERSONAL_ACCESS_TOKEN` 在环境或仓库 `.env` 中；运行消耗真实额度。
- **S 层**无需 Gmail / iCloud 凭证（两域 `unconfigured`，其余功能可用）。
- **M/C/F/L 层**需要专用一次性测试账号，接入前不注册进场景登记表；真实外部写只落在测试账号。

## 运行

仓库根执行：

```bash
uv run --project server python -m evaluation.run --scenario S2,S3 [--repeat N] [--model ID]
```

- 每次重复独立实例（临时数据目录 + 独立端口），种子在启动前铺好。
- 产物在 `.eval-results/<时间戳>/`（时间戳与报告时间均为 UTC+8）：`report.md` / `report.json`、每次重复的 `data/` 与 `server.log`（证据保留，目录已被 gitignore）。报告含逐轮详情：用户消息、助手回复、完整工具参数与返回内容、每轮用量。
- 退出码：全部通过且红线零违规为 0。
- S1 核对成功的资料库返回是否包含现行《家庭保险》的事实片段；通用 `review_task` 接收任务、预期、参考材料和按顺序排列的轮次记录（含工具调用结果），分别评估任务完成情况和过程合理性。单次评审中信息不足、格式无效或模型失败标「待复核」，退出码非零。自动化测试验证输入传递和结果处理；真实评审模型的判别力尚未校准。
- S2 从未教过生日和例会的种子起步，教会两条长期信息，隔两个独立任务再问洗牙时间，并检查临时疲惫状态不入记忆。
- S3 从尚未整理的资料种子起步，驱动器直接改隔离实例的 `kb/` 文件，再通过产品接口触发收编与检索；核对移动同 id、复制新 id、删除仍可从本地版本历史恢复。
- S4 在助手本轮成功读取《家庭保险》旧版后，通过与资料管理页相同的接口先保存用户改动；检查终稿保留双方内容，以及版本冲突后的重读和成功修改。若未抢在助手修改前保存，报告为未形成预期竞争，不当作冲突恢复通过。
- 当前报告用量仅来自产品轮次观测，不含评审调用；不能据此报告完整评测成本。

## 结构

```
harness/    基础设施：config（配置）、server（隔离实例）、client（驱动器）、
            seeds（种子）、model（场景/断言模型）、checks（横切断言）、report（报告）
scenarios/  场景：common（林然基线种子）+ 各场景文件
run.py      入口
```

## 状态

- 已落地：S1（保险笔记问答）、S2（教偏好与生日）、S3（编辑器直改资料库）、S4（补写时用户先保存）。S5–S9、M/C/F/L 各场景按 `docs/evaluation.md` §4.4 基线清单逐个接入。
- 横切断言分三层（规格 §5）：轮次终态（计分）；越权工具调用必被拒绝（红线绊线，
  真的执行成功才计违规）；观测不变量与材料字符预算（取证自检 `infra=True`，
  失败记基础设施故障、不计入场景判定，报告单列 🟡）。
- 程序事务类保证（并发确认唯一成功、来信去重幂等、冲突不覆盖机制）由 pytest 承担，不进场景库。
