# 真实场景评测运行器

`docs/evaluation.md` 的实现载体：在真实模型、真实产品接口下驱动隔离实例，
验证产品行为（pytest 用替身锁程序逻辑，二者互补）。

## 前提

- **模型凭证**：`QODERCN_PERSONAL_ACCESS_TOKEN` 在环境或仓库 `.env` 中；运行消耗真实额度。
- **S 层**无需 Gmail / iCloud 凭证（两域 `unconfigured`，其余功能可用）。
- **M/C/F/L 层**需要专用一次性测试账号，接入前不注册进场景登记表；真实外部写只落在测试账号。

## 运行

仓库根执行：

```bash
uv run --project server python -m evaluation.run --scenario S1 [--repeat N] [--model ID]
```

- 每次重复独立实例（临时数据目录 + 独立端口），种子在启动前铺好。
- 产物在 `.eval-results/<时间戳>/`：`report.md` / `report.json`、每次重复的 `data/` 与 `server.log`（证据保留，目录已被 gitignore）。报告含逐轮详情：用户消息、助手回复、工具调用与状态、每轮用量。
- 退出码：全部通过且红线零违规为 0。
- S1 核对成功的资料库返回是否包含现行《家庭保险》的事实片段；再独立调用两次轻量模型，按固定问题判断现行结论和额外事实。两次不一致、评审格式无效或模型失败时标「待复核」，退出码非零。合成反例已校准解析与汇总逻辑；评审模型的真实判别力尚需单独验证。
- 当前报告用量仅来自产品轮次观测，不含这两次评审调用；不能据此报告完整评测成本。

## 结构

```
harness/    基础设施：config（配置）、server（隔离实例）、client（驱动器）、
            seeds（种子）、model（场景/断言模型）、checks（横切断言）、report（报告）
scenarios/  场景：common（林然基线种子）+ 各场景文件
run.py      入口
```
